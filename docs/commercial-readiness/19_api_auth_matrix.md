## Reading This Matrix

`middleware.ts` allows `/api/auth/login` and `/api/health`, then skips other `/api/*` paths. Treat middleware as page-route protection only; every API route must self-protect unless it is explicitly public-by-design.

Access classes used below:

- `public-by-design`: intentionally unauthenticated.
- `self-service-auth`: current-session auth operation.
- `authenticated`: an authenticated caller with an active application-user row. Story 22.15 makes the database role helper return `NULL` for inactive/missing rows.
- `role-restricted`: explicit role or field-permission restriction.
- `hr-admin-only`: `hr_admin` only.
- `employee-manager`: `hr_admin` or `recruiter`.
- `cron-secret`: protected by `CRON_SECRET`.

Evidence statuses used below:

- `verified`: static route code shows the expected helper/policy source.
- `verified-with-follow-up`: static protection exists, but a service-role bypass, app-layer-only control, or missing `request` helper call needs follow-up evidence.
- `risk-flagged`: route has a concrete risk or weak protection that should be remediated or tested.
- `public-by-design`: intentionally public route.
- `cron-secret`: cron-secret route.

Request-cookie status:

- `request-passed`: helper or Supabase API client receives `request`.
- `missing-request-follow-up`: API helper is called without `request` despite the documented API cookie workaround in `src/lib/server/auth.ts` and `src/lib/supabase/server-api.ts`.
- `direct-cookie-client`: route uses `createClient()`/`getUserFromSession()` without `request`.
- `not-applicable`: no session-cookie auth expected.
