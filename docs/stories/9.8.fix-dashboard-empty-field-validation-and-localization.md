## Context

For fields that are initially empty, if a user starts inline editing and then leaves the value still empty, a warning “invalid value” appears. This is incorrect, and the message is in English instead of Swedish.

This story ensures that unchanged empty fields do not show validation errors, that true invalid values still show an error, and that the error text is properly localized to Swedish.

## User Stories

As an HR user,  
I do not want to see an error when I leave an empty field empty  
so that I am not blocked or confused by false validation errors.

As a Swedish-speaking user,  
I want validation error messages in Swedish  
so that the UI is understandable and consistent.

## Scope / Notes

- Apply this to all relevant inline-editable fields where empty is a valid state.  
- Ensure “invalid value” errors are shown only when the value is truly invalid per business rules.  
- Wire validation messages through our i18n/localization system.  
- Ensure no-op edits (entering edit mode and leaving the value unchanged) do not send updates, trigger redundant rerenders, or raise spurious validation.

## Acceptance Criteria

- **AC1 – No warning for unchanged empty field**  
  - Given a field is initially empty and empty is allowed  
  - When I enter inline-edit mode and exit without entering a value  
  - Then no “invalid value” (or similar) error is shown.

- **AC2 – Real invalid values still warned**  
  - Given a field has validation rules (format, range, etc.)  
  - When I enter an actual invalid value  
  - Then a validation error is shown.

- **AC3 – Message text in Swedish**  
  - When an invalid value validation error is shown  
  - Then the message text is “Ogiltigt värde” (or another agreed Swedish string)  
  - And it is not shown in English.

- **AC4 – Consistency across fields**  
  - When I trigger validation across similar fields on the dashboard  
  - Then the same rules apply consistently (no error for unchanged empty, Swedish error text).

- **AC5 – No-op edit does not cause updates or extra renders**  
  - Given any inline-editable field (where empty or some value is allowed)  
  - When I enter edit mode and exit without changing the value  
  - Then no update is sent and no redundant rerender or spurious validation is triggered.

- **AC6 – Dashboard tests updated and passing**  
  - When this story is completed  
  - Then tests exist/are updated for: unchanged empty field behavior, Swedish “Ogiltigt värde” messaging, and no-op edit handling  
  - And the dashboard test suite passes.
