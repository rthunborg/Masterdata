8. Existing data migration handles invalid values (convert non-numeric to NULL)
9. Translation keys for "Lönenivå" = "Salary Level" (EN) / "Lönenivå" (SV)
10. Sorting by Lönenivå works correctly (0,1,2...7, then NULL values at end)
11. Export displays Lönenivå value or "Not Set" for NULL
12. Column Settings allows toggling Lönenivå visibility

### Database Schema

**Migration SQL:**

```sql
-- Step 1: Backup existing data (optional, for safety)
ALTER TABLE employees ADD COLUMN loneiva_backup TEXT;
UPDATE employees SET loneiva_backup = loneiva;

-- Step 2: Clean invalid data (convert non-numeric to NULL)
UPDATE employees SET loneiva = NULL WHERE loneiva !~ '^[0-9]+$' OR loneiva::integer < 0 OR loneiva::integer > 7;

-- Step 3: Convert column type to INTEGER
ALTER TABLE employees ALTER COLUMN loneiva TYPE INTEGER USING loneiva::integer;

-- Step 4: Add CHECK constraint
ALTER TABLE employees
ADD CONSTRAINT employees_loneiva_check
CHECK (loneiva >= 0 AND loneiva <= 7 OR loneiva IS NULL);

-- Step 5: Add column comment for documentation
COMMENT ON COLUMN employees.loneiva IS 'Salary level (0-7 scale, nullable)';

-- Step 6: Drop backup column after verification (optional)
-- ALTER TABLE employees DROP COLUMN loneiva_backup;
```

**Constraint Details:**

- **Type:** INTEGER (numeric, not text)
- **Valid Range:** 0, 1, 2, 3, 4, 5, 6, 7, or NULL
- **Default:** NULL (not set)
- **Database-Level Enforcement:** CHECK constraint prevents invalid values at schema level

**Migration Safety:**

The migration includes data cleaning logic to handle existing invalid TEXT values. Any non-numeric or out-of-range values are converted to NULL. The optional backup column (`loneiva_backup`) preserves original data for manual review if needed.

### Sorting Logic

**Numeric Sorting with NULL Handling:**

Location: `src/components/dashboard/employee-table.tsx`

```typescript
{
  accessorKey: 'loneiva',
  header: ({ column }) => (
    <Button
      variant="ghost"
      onClick={() => column.toggleSorting(column.getIsSorted() === 'asc')}
    >
      {t('employee.loneiva.label')}
      <ArrowUpDown className="ml-2 h-4 w-4" />
    </Button>
  ),
  cell: ({ row }) => (
    <EditableCell
      value={row.original.loneiva}
      employeeId={row.original.id}
      field="loneiva"
      type="number"
      onSave={handleSave}
      canEdit={canEdit}
    />
  ),
  sortingFn: (rowA, rowB, columnId) => {
    const a = rowA.getValue<number | null>(columnId);
    const b = rowB.getValue<number | null>(columnId);

    // NULL values always sort to the end
    if (a === null && b === null) return 0;
    if (a === null) return 1; // a after b
    if (b === null) return -1; // b after a

    // Normal numeric comparison
    return a - b;
  },
}
```

**Sorting Behavior:**

- Ascending: 0, 1, 2, 3, 4, 5, 6, 7, [NULL values]
- Descending: 7, 6, 5, 4, 3, 2, 1, 0, [NULL values]
- NULL values always appear at the end regardless of sort direction

### Business Rule Context

**Salary Level Scale:**

The Lönenivå (Salary Level) field uses a 0-7 numeric scale to classify employee compensation levels. This standardized scale enables:

1. **Reporting Consistency:** HR can generate accurate salary distribution reports
2. **Compensation Planning:** Track salary progression across employee lifecycle
3. **Budget Forecasting:** Aggregate salary levels for financial planning
4. **Compliance:** Maintain structured salary classification for auditing purposes

The green badge provides visual confirmation that an employee's salary level has been classified, ensuring no employees are missing this critical data point during onboarding or compensation reviews.

**Empty/Null Value Semantics:**

- NULL value = "Not yet classified" (common for new employees)
- NOT an error state, just incomplete data
- HR workflow: Employee created → Initial data entered → Salary level assigned later
