## A1: Content-Type Header Format Change (5 failures)

### Root Cause

The implementation was updated to include charset information in the Content-Type header for better CSV encoding support. This is a **correct implementation change** that improves Excel compatibility.

**Old Expected Behavior:**
- Content-Type: `"text/csv"`

**New Expected Behavior:**
- Content-Type: `"text/csv; charset=utf-8"`

**Related Epic 13 Stories:**
- 13.4: Export Only Selected Employees
- 13.6: General Export Button with Field Selection
- 13.7: Write Comprehensive Export Tests

**Evidence:**
- Implementation correctly sets `"text/csv; charset=utf-8"` in export API routes
- This follows HTTP best practices for CSV content with UTF-8 encoding
- Improves Excel compatibility when opening exported files

**Fix Strategy:**
Update test assertions to expect `"text/csv; charset=utf-8"` instead of `"text/csv"`.

**Status:** ✅ **FIXED** - All Content-Type assertions have been updated to expect `"text/csv; charset=utf-8"`

## A2: CSS Class Name Changes - Selection Styling (3 failures)

### Root Cause

The selection styling was changed from solid background to semi-transparent background to allow combining with status tints (terminated red, crew ready green).

**Old Expected Behavior:**
- Selected rows: `bg-gray-100 dark:bg-gray-800` (solid background)

**New Expected Behavior:**
- Selected rows: `bg-gray-100/50 dark:bg-gray-800/50` (semi-transparent, allows combining with status tints)

**Related Epic 13 Stories:**
- 13.2: Add Employee Row Selection Checkboxes
- 13.3: Implement Row Click Selection
- 13.11: Visual Indicators for Employee Status

**Evidence:**
- Implementation at `employee-table.tsx:2356` uses `bg-gray-100/50 dark:bg-gray-800/50`
- This allows status tints (red/green) to show through the selection tint
- Matches Story 13.11 AC requirement: "the red tint is still visible (selection grey doesn't completely override status tint)"

**Fix Strategy:**
Update test assertions to expect `bg-gray-100/50` or use `.toContain("bg-gray-100")` for flexible matching.

**Status:** ✅ **FIXED** - All selection styling tests have been updated to expect `bg-gray-100/50`

---

## A3: CSS Class Changes - Status Tints (3 failures)

### Root Cause

Status tint implementation uses background colors (not text colors) and combines with selection tint using opacity.

**Old Expected Behavior:**
- Terminated employees: `text-red-800` (text color)
- Status tints override selection tint completely

**New Expected Behavior:**
- Terminated employees: `bg-red-50 dark:bg-red-950/20` (background color)
- Crew ready employees: `bg-green-50/50 dark:bg-green-950/20` (background color)
- Status tints combine with selection tint using opacity (both visible)

**Related Epic 13 Stories:**
- 13.11: Visual Indicators for Employee Status

**Evidence:**
- Implementation at `employee-table.tsx:2345-2347`:
  - Terminated: `bg-red-50 dark:bg-red-950/20`
  - Crew ready: `bg-green-50/50 dark:bg-green-950/20`
  - Selection: `bg-gray-100/50 dark:bg-gray-800/50` (combines with status tints)
- Story 13.11 AC: "the red tint is still visible (selection grey doesn't completely override status tint)"
- Text color `text-red-800` was removed for better readability per Story 13.11 Dev Notes

**Fix Strategy:**
1. Remove any expectations for `text-red-800` class
2. Update tests to expect background color classes: `bg-red-50`, `bg-green-50/50`
3. Update tests to expect both status tint AND selection tint when row is selected (both should be present)

**Status:** ✅ **FIXED** - Status tint tests have been updated to expect background colors and account for combination with selection
