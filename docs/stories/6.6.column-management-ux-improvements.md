# Story 6.6: Column Management UX Improvements

## Status

**Done**

---

## Story

**As an** HR Admin,  
**I want** clear visual feedback for hidden columns and the ability to reorder columns via drag-and-drop,  
**so that** I can customize the table layout for my workflow.

---

## Acceptance Criteria

1. **Add Column Button:**
   - "Add Column" button visible on Column Settings page for HR Admin
   - Opens modal with fields: Column Name, Data Type (Text/Number/Date/Boolean), Category (optional)
   - Clicking "Create" adds column to column_config table and makes it visible in employee table

2. **Hide Column Visual Feedback:**
   - Hidden columns show "Hidden" badge in Column Settings table
   - Visible columns show "Visible" badge or checkmark icon
   - Toggle button changes text: "Hide" ⇄ "Show" based on current state
   - Hidden columns do NOT appear in employee table (already implemented, just need visual indicator)

3. **Drag-and-Drop Column Reordering:**
   - Drag handle icon (☰) on each column row in Column Settings table
   - HR Admin can drag columns to reorder them
   - New order saved to `column_config.display_order` field (new database column)
   - Employee table columns render in order specified by `display_order`
   - Reordering is persistent across sessions

4. **Database Schema Update:**
   - Add `display_order` column to `column_config` table (integer, default 0)
   - Migration script to populate default order for existing columns

5. **Responsive Design:**
   - Drag-and-drop works on desktop (mouse)
   - Mobile: Show "Move Up" / "Move Down" buttons instead of drag-and-drop

6. **Translations:**
   - "Add Column" button translated
   - "Hidden" / "Visible" badges translated
   - Drag handle accessible label: "Reorder column" (English) / "Ordna kolumn" (Swedish)

### ✅ Authentication Best Practices (From Post-Mortem Analysis)

**Supabase SSR Authentication Rules:**

1. **ALWAYS use `getUser()` for auth checks** (validates JWT server-side)
   - ❌ NEVER use `getSession()` in middleware or pages (only reads cookies, no validation)
   - ✅ Correct: `const { data: { user } } = await supabase.auth.getUser();`
   - ❌ Wrong: `const { data: { session } } = await supabase.auth.getSession();`

2. **Use `window.location.href` for redirects after login** (forces full page reload)
   - ❌ NEVER use `router.push()` after authentication state change (client-side navigation doesn't sync cookies)
   - ✅ Correct: `window.location.href = "/dashboard";`
   - ❌ Wrong: `router.push("/dashboard");`

3. **Server components for auth-dependent pages** (no client-side auth checks)
   - ✅ Root pages (`page.tsx`) should be async server components
   - ✅ Auth check happens on server before rendering
   - ❌ Don't use client components with `useEffect` auth checks (causes flashing)

4. **Consistent auth checks across all entry points**
   - Middleware checks auth for route protection
   - Page components check auth for redirects
   - Both must use `getUser()` (not `getSession()`)

**Testing Checklist Before ANY Auth/Routing Change:**

```sql
CREATE TABLE column_config (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  data_type TEXT NOT NULL, -- 'text', 'number', 'date', 'boolean'
  category TEXT,

  updated_at TIMESTAMPTZ DEFAULT now()

```

**Migration to Add (Task 1.1):**

```sql
-- Add display_order column
ALTER TABLE column_config
ADD COLUMN display_order INTEGER DEFAULT 0;

-- Populate default order for existing columns
UPDATE column_config
SET display_order = row_number
FROM (
  SELECT id, ROW_NUMBER() OVER (ORDER BY created_at) AS row_number
  FROM column_config
) AS ordered_columns
WHERE column_config.id = ordered_columns.id;
```

### Drag-and-Drop Implementation Pattern

[Source: dnd-kit documentation, React best practices]

**Library Choice: @dnd-kit**

- Modern, accessible, performant
- Touch-friendly for mobile
- TypeScript support
- Active maintenance
- React 18+ compatible

**Basic Implementation Pattern:**

```tsx
import {
  DndContext,
  closestCenter,
  KeyboardSensor,
  PointerSensor,
  useSensor,
  useSensors,
} from '@dnd-kit/core';
import {
  arrayMove,
  SortableContext,
  sortableKeyboardCoordinates,
  verticalListSortingStrategy,
  useSortable,
} from '@dnd-kit/sortable';
import { CSS } from '@dnd-kit/utilities';

// Sortable row component
function DraggableColumnRow({ column }) {
  const {
    attributes,
    listeners,
    setNodeRef,
    transform,
    transition,
    isDragging,
  } = useSortable({ id: column.id });

  const style = {
    transform: CSS.Transform.toString(transform),
    transition,
    opacity: isDragging ? 0.5 : 1,
  };

  return (
    <tr ref={setNodeRef} style={style}>
      <td>
        <button {...attributes} {...listeners} aria-label="Reorder column">
          ☰
        </button>
      </td>
      <td>{column.column_name}</td>
      {/* Other cells */}
    </tr>
  );
}

// Parent table component
function ColumnSettingsTable({ columns }) {
  const [items, setItems] = useState(columns);
  const sensors = useSensors(
    useSensor(PointerSensor),
    useSensor(KeyboardSensor, {
      coordinateGetter: sortableKeyboardCoordinates,
    })
  );

  function handleDragEnd(event) {
    const { active, over } = event;
    if (active.id !== over.id) {
      setItems((items) => {
        const oldIndex = items.findIndex((item) => item.id === active.id);
        const newIndex = items.findIndex((item) => item.id === over.id);
        const newItems = arrayMove(items, oldIndex, newIndex);

        // Update display_order based on new array position
        const updates = newItems.map((item, index) => ({
          id: item.id,
          display_order: index,
        }));

        // Call API to persist changes
        fetch('/api/column-config/reorder', {
          method: 'PATCH',
          body: JSON.stringify({ columns: updates }),
        });

        return newItems;
      });
    }
  }

  return (
    <DndContext
      sensors={sensors}
      collisionDetection={closestCenter}
      onDragEnd={handleDragEnd}
    >
      <SortableContext items={items} strategy={verticalListSortingStrategy}>
        <table>
          <thead>{/* headers */}</thead>
          <tbody>
            {items.map((column) => (
              <DraggableColumnRow key={column.id} column={column} />
            ))}
          </tbody>
        </table>
      </SortableContext>
    </DndContext>
  );
}
```

**POST /api/column-config (Add Column):**

```typescript
// src/app/api/column-config/route.ts
import { requireHRAdminAPI } from '@/lib/auth-helpers';
import { addColumnSchema } from '@/lib/validation/column-schema';

export async function POST(request: Request) {
  // Auth check
  const { user } = await requireHRAdminAPI();

  // Validate request
  const body = await request.json();
  const validation = addColumnSchema.safeParse(body);
  if (!validation.success) {
    return NextResponse.json(
      { error: validation.error.flatten() },
      { status: 400 }
    );
  }

  // Get max display_order
  const { data: maxOrder } = await supabase
    .from('column_config')
    .select('display_order')
    .order('display_order', { ascending: false })
    .limit(1)
    .single();

  // Insert new column
  const { data, error } = await supabase
    .from('column_config')
    .insert({
      column_name: validation.data.column_name,
      data_type: validation.data.data_type,
      category: validation.data.category || null,
      is_visible: true,
      is_system: false,
      display_order: (maxOrder?.display_order ?? 0) + 1,
    })
    .select()
    .single();

  if (error) {
    return NextResponse.json({ error: error.message }, { status: 500 });
  }

  return NextResponse.json({ data }, { status: 201 });
}
```

**PATCH /api/column-config/reorder (Reorder Columns):**

```typescript
// src/app/api/column-config/reorder/route.ts
export async function PATCH(request: Request) {
  const { user } = await requireHRAdminAPI();

  const body = await request.json();
  const { columns } = body; // Array of { id, display_order }

  // Validate columns array
  if (!Array.isArray(columns) || columns.length === 0) {
    return NextResponse.json(
      { error: 'Invalid columns array' },
      { status: 400 }
    );
  }

  // Batch update using transaction
  const updates = columns.map((col) =>
    supabase
      .from('column_config')
      .update({ display_order: col.display_order })
      .eq('id', col.id)
  );

  const results = await Promise.all(updates);

  // Check for errors
  const errors = results.filter((r) => r.error);
  if (errors.length > 0) {
    return NextResponse.json(
      { error: 'Failed to update column order' },
      { status: 500 }
    );
  }

  return NextResponse.json({ success: true }, { status: 200 });
}
```

### Known Issues and Edge Cases

**Edge Case 1: Concurrent Reordering**

- **Scenario:** Two HR Admins reorder columns simultaneously
- **Solution:** Last write wins (acceptable for column settings)
- **Future:** Add optimistic locking or conflict detection

**Edge Case 2: Deleting Column During Reorder**

- **Scenario:** Column deleted while drag-and-drop in progress
- **Solution:** Refresh column list after any CRUD operation
- **Implementation:** Use React Query or SWR for automatic refetch

**Edge Case 3: Very Long Column Names**

- **Scenario:** Column name exceeds table cell width
- **Solution:** Truncate with ellipsis, show full name on hover
- **CSS:** `overflow: hidden; text-overflow: ellipsis; white-space: nowrap;`

**Edge Case 4: Mobile Drag Conflicts with Scroll**

- **Scenario:** Touch drag interferes with page scroll
- **Solution:** Use "Move Up/Down" buttons on mobile (AC 5)
- **Implementation:** `useMediaQuery('(max-width: 768px)')` to toggle UI

**Edge Case 5: System Columns**

- **Scenario:** User tries to delete system columns (SSN, name, etc.)
- **Solution:** `is_system = true` columns cannot be deleted/hidden
- **UI:** Disable "Hide" button for system columns
- **Note:** This story doesn't implement delete, but future-proofs schema
