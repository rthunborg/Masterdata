# Story 8.4: Talmundo Field with Conditional Editability

## Status

**Done**

## Story

**As an** HR Admin,  
**I want** Talmundo field to only be editable when One is green (24+ hours),  
**So that** I enforce the correct operational sequence.

---

## Acceptance Criteria

1. Database adds `talmundo` BOOLEAN column to employees table
2. Talmundo field displays in employee table for HR Admin role
3. Talmundo field is disabled (grayed out, no click action) when One field is false
4. Talmundo field is disabled when One field is yellow (< 24 hours elapsed)
5. Talmundo field is enabled (clickable, editable) when One field is green (>= 24 hours)
6. Tooltip on disabled Talmundo shows: "Can only be edited after One field completes 24-hour sync to Talmundo system"
7. When enabled and set to true, display green badge ("✓ Complete")
8. API validation prevents editing Talmundo unless One is true and >= 24 hours elapsed
9. Employee create form shows Talmundo field as disabled by default (since One is false)
10. Form validation provides clear error message if user attempts to bypass client-side validation
11. Column Settings allows HR Admin to show/hide Talmundo column
12. Talmundo field seeds into column_config with is_masterdata=true, HR Admin only

### Architecture Context

This story implements conditional field editability based on the One field's time-based status. The Talmundo field represents completion of the external Talmundo system synchronization, which can only proceed after the One field has been true for at least 24 hours. This enforces the correct operational sequence and prevents data integrity issues from premature editing.

- `one_marked_at` timestamp column tracking when One was set to true
- `getOneFieldStatus()` function calculating yellow (< 24 hours) vs green (>= 24 hours) status
- Real-time badge updates showing pending/complete status
- Timezone-safe UTC timestamp handling

Story 8.4 builds directly on this infrastructure by using the One field status to control Talmundo field editability.

### Business Logic Service

**File Location:** `src/lib/services/talmundo-validation.ts`

**Function Specification:**

```typescript
import { getOneFieldStatus } from './one-field-status';

/**
 * Determine if Talmundo field can be edited based on One field status.
 *
 * Business Rule: Talmundo field requires One field to be true for >= 24 hours
 * before editing is allowed. This enforces the correct operational sequence
 * and prevents premature editing during the Talmundo system sync period.
 *
 * @param oneValue - Current boolean value of the One field
 * @param oneMarkedAt - Timestamp when One was set to true (ISO 8601 format)
 * @returns true if Talmundo can be edited (One is green), false otherwise
 */
export function canEditTalmundo(
  oneValue: boolean | null,
  oneMarkedAt: string | null
): boolean {
  // If One is not true, Talmundo cannot be edited
  if (!oneValue) return false;

  // Calculate One field status (yellow = pending, green = ready)
  const oneStatus = getOneFieldStatus(
    oneValue,
    oneMarkedAt ? new Date(oneMarkedAt) : null
  );

  // Talmundo can only be edited when One field is green (24+ hours elapsed)
  return oneStatus === 'green';
}
```

**Dependency:** This service depends on `getOneFieldStatus()` from Story 8.3, which must be implemented first.

```typescript
interface EditableCellProps {
  // ... existing props
  canEdit?: boolean;
  oneValue?: boolean | null; // For Talmundo field only
  oneMarkedAt?: string | null; // For Talmundo field only
}

export function EditableCell({
  value,
  employeeId,
  field,
  type,
  options,
  canEdit = true,
  oneValue,
  oneMarkedAt,
  onSave,
  onError,
}: EditableCellProps) {
  // Determine if this is the Talmundo field
  const isTalmundoField = field.toLowerCase() === 'talmundo';

  // Calculate conditional editability for Talmundo
  const effectiveCanEdit = isTalmundoField
    ? canEditTalmundo(oneValue ?? false, oneMarkedAt ?? null)
    : canEdit;

  // Disabled state styling
  const disabledClass = !effectiveCanEdit ? 'opacity-50 cursor-not-allowed' : '';

  // Read mode rendering with conditional tooltip
  if (!isEditing) {
    const content = (
      <div
        className={cn(
          'flex items-center gap-2 px-3 py-2',
          effectiveCanEdit && 'cursor-pointer hover:bg-muted/50',
          disabledClass
        )}
        onClick={() => effectiveCanEdit && setIsEditing(true)}
      >
        <span>{displayValue}</span>
        {type === 'boolean' && value && <StatusBadge status="green" />}
      </div>
    );

    // Wrap disabled Talmundo in tooltip
    if (isTalmundoField && !effectiveCanEdit) {
      return (
        <Tooltip>
          <TooltipTrigger asChild>{content}</TooltipTrigger>
          <TooltipContent>
            <p>Can only be edited after One field completes 24-hour sync to Talmundo system</p>
          </TooltipContent>
        </Tooltip>
      );
    }

    return content;
  }

  // ... rest of component (edit mode logic)
}
```

### Business Rule Clarification

**Context: Talmundo System Integration**

As documented in Epic 8 Business Rule Clarifications, the One field triggers data synchronization to the Talmundo external system. The system requires a **24-hour processing window** to complete the sync.

The Talmundo field represents the completion status of the Talmundo system integration itself. Allowing users to edit Talmundo before the One field sync completes would create data inconsistencies and integration errors.

By enforcing the 24-hour waiting period through conditional editability:

1. Data integrity is maintained between HR system and Talmundo
2. Users cannot accidentally create invalid state (Talmundo=true when sync hasn't completed)
3. Clear visual feedback (disabled state + tooltip) prevents confusion
4. Server-side validation provides security layer against API manipulation
