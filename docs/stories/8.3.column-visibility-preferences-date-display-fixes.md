# Story 8.3: Column Visibility Preferences, Date Display Fix, and Inline Date Selection

## Status

**Done**

---

## Story

**As a** HR Admin user,  
**I want** to hide columns I don't need to view, see Important Date fields displayed as readable dates instead of GUIDs, have inline editing show only relevant date options, filter Important Dates by PE3 category, and view the Column Settings table without horizontal scrolling,  
**so that** I can customize my view to focus on relevant information, easily read and manage date values throughout the system, and access all administrative functions without layout issues.

---

## Acceptance Criteria

### AC 1: HR Admin Personal Column Visibility Preferences

1. **Column Visibility Toggle Interface**: HR Admin users must see an "eye" icon or visibility toggle option for each column in the employee table dashboard
2. **Hide/Show Column Functionality**: Clicking the visibility toggle must immediately hide or show the column in the HR Admin's personal view without affecting:
   - Column permissions (other users' access)
   - Column configuration in the database
   - Other HR Admin users' column visibility preferences
3. **Persistence**: Column visibility preferences must persist across browser sessions using browser localStorage
4. **Visual Indicator**: Hidden columns must remain accessible through a "Show Hidden Columns" menu or similar interface
5. **Reset Option**: HR Admin must have an option to "Reset to Default" visibility (show all columns they have view permission for)
6. **Performance**: Toggling column visibility must update the table view in <200ms without full page reload

### AC 2: Display Important Date Values Instead of GUIDs

1. **Readable Date Display**: In the employee table dashboard, the following columns must display human-readable date information instead of UUIDs/GUIDs:
   - `Stena Date` column - Display: `date_description` from linked `important_dates` record (e.g., "Fredag 14/2")
   - `ÖMC Date` column - Display: `date_description` from linked `important_dates` record
   - `PE3 Date` column - Display: `date_description` from linked `important_dates` record (or empty if null)
2. **Fallback Display**: If a date ID references a deleted `important_dates` record, display: "(Date not found)" with styling to indicate data issue
3. **Null Handling**: If date field is null/empty, display empty cell (not "null" or "undefined")
4. **Tooltip Enhancement**: Hovering over a date cell must show a tooltip with full date details:
   - Week number (if available)
   - Year
   - Date value
   - Category
5. **Sorting Compatibility**: Date columns must remain sortable by the underlying `important_dates` week_number and year (chronological order)

### AC 3: Inline Date Editing with Category-Filtered Dropdowns

1. **Stena Date Inline Edit**: When clicking to edit the `Stena Date` cell, a dropdown must appear showing ONLY Important Dates where `category = "Stena Dates"`, ordered by year and week_number ascending
2. **ÖMC Date Inline Edit**: When clicking to edit the `ÖMC Date` cell, dropdown shows ONLY `category = "ÖMC Dates"` options
3. **PE3 Date Inline Edit**: When clicking to edit the `PE3 Date` cell, dropdown shows ONLY `category = "PE3 Dates"` options AND only dates not already assigned to other employees (enforces uniqueness per Story 6.2)
4. **Dropdown Display Format**: Each dropdown option must show: `{date_description} (Week {week_number}, {year})` (e.g., "Fredag 14/2 (Week 7, 2025)")
5. **Future Dates Only**: Dropdowns must filter out past dates (date_value < today) to prevent assignment of outdated dates
6. **Clear/Remove Option**: Each date dropdown must include a "Clear" or "(None)" option to allow removing the date assignment (setting field to null)
7. **Real-time Date Lookup**: When save is triggered, the selected Important Date ID must be stored in the `employees` table fields (`stena_date`, `omc_date`, `pe3_date`)
8. **Edit Permission Respect**: Only users with `edit` permission for these columns (HR Admin) can trigger inline editing; others see read-only display

### AC 4: Update Column Mapping for Date Resolution

1. **Column Mapping Enhancement**: The `getEmployeeFieldValue()` utility function in `src/lib/utils/column-mapping.ts` must be enhanced to:
   - Detect when a column name is "Stena Date", "ÖMC Date", or "PE3 Date"
   - If the field value is a UUID, perform a lookup to fetch the matching `important_dates` record
   - Return the `date_description` field from the fetched record
   - Cache lookups to avoid repeated database queries for the same date IDs within a render cycle
2. **Table Cell Renderer Update**: The `employee-table.tsx` component's cell renderer must:
   - Pass full Important Date object (not just ID) to the EditableCell component for date columns
   - Provide the filtered list of applicable Important Dates based on category to EditableCell

### AC 5: Add PE3 Dates Category Filter to Important Dates Page

1. **Category Filter Options**: The Important Dates page filter dropdown must include "PE3 Dates" as a selectable category option alongside existing "Stena Dates", "ÖMC Dates", and "Other"
2. **Filter Functionality**: Selecting "PE3 Dates" from the filter dropdown must filter the Important Dates table to show only records where `category = "PE3 Dates"`
3. **Translation Support**: Category filter option must display translated text:
   - English: "PE3 Dates"
   - Swedish: "PE3-datum" (should already exist from Story 8.2)
4. **Consistency**: Filter behavior must match existing category filter functionality (no changes to filter logic, just add the missing option)

### AC 6: Remove Horizontal Scrollbar from Column Settings Table

1. **Responsive Layout**: The Column Settings table in Admin > Column Settings must expand to full viewport width without requiring horizontal scrolling
2. **Column Width Optimization**: Table columns must resize/wrap content appropriately to fit within viewport:
   - Column Name: Flexible width (min 150px)
   - Type: Fixed narrow width (~80px)
   - Category: Medium width (~120px)
   - Permission toggles: Fixed width per role (~100px each)
   - Actions: Fixed narrow width (~80px)
3. **Breakpoint Behavior**:
   - Desktop (≥1024px): All columns visible in single row without scroll
   - Tablet (768-1023px): Consider stacking permission toggles or using responsive cards
   - Mobile (<768px): Use existing card view (already implemented in Story 8.1)
4. **No Data Loss**: All information must remain visible and accessible without horizontal scrolling on desktop viewports (1280px and above)
5. **Table Layout**: Use responsive table layout with `table-layout: auto` or CSS Grid to allow flexible column sizing instead of fixed widths

### Data Flow for Date Display

**Current Problem:**

1. Employee table queries `employees` table
2. Fields `stena_date`, `omc_date`, `pe3_date` contain UUID strings (e.g., "a1b2c3d4-5678-...")
3. These UUIDs are displayed directly in table cells → users see GUIDs

**Solution Flow:**

1. Employee table component fetches ALL important_dates using `useImportantDates()` (no category filter)
2. When rendering each employee row, for date columns:
   - Current value is UUID string from employee.stena_date (etc.)
   - Call `resolveImportantDateId(uuid, allImportantDates)` → returns "Fredag 14/2"
   - Display resolved description in table cell
3. When user clicks to edit:
   - Render EditableDateCell component
   - Filter allImportantDates by category ("Stena Dates", etc.)
   - Populate Select dropdown with filtered dates
   - Display as: "{date_description} (Week {week_number}, {year})"
4. When user selects a date:
   - Extract selected ImportantDate object
   - Save `date.id` (UUID) to employees.stena_date field via API
5. After save:
   - Table re-renders with new UUID
   - Resolution utility resolves to new description
   - User sees updated readable date

### Important Date Resolution Caching

To avoid repeated database lookups or array searches, implement simple memoization:

```typescript
// In employee-table.tsx
const dateResolutionCache = React.useMemo(() => {
  const cache = new Map<string, string>();
  allImportantDates.forEach((date) => {
    cache.set(date.id, date.date_description);
  });
  return cache;
}, [allImportantDates]);

// In resolveImportantDateId utility
export function resolveImportantDateId(
  dateId: string | null,
  datesOrCache: ImportantDate[] | Map<string, string>
): string {
  if (!dateId) return '';

  if (datesOrCache instanceof Map) {
    return datesOrCache.get(dateId) || '(Date not found)';
  }

  // Array path (fallback)
  const date = datesOrCache.find((d) => d.id === dateId);
  return date ? date.date_description : '(Date not found)';
}
```

### Sorting Date Columns

Current implementation uses `sortingFn` for date columns that parses date strings. Need to update for UUID-based dates:

```typescript
// In employee-table.tsx column definition
{
  accessorKey: "stena_date",
  enableSorting: true,
  sortingFn: (rowA, rowB) => {
    const dateA = getImportantDateById(rowA.original.stena_date, allImportantDates);
    const dateB = getImportantDateById(rowB.original.stena_date, allImportantDates);

    if (!dateA && !dateB) return 0;
    if (!dateA) return 1;
    if (!dateB) return -1;

    // Sort by year, then week_number
    if (dateA.year !== dateB.year) {
      return dateA.year - dateB.year;
    }
    return (dateA.week_number || 0) - (dateB.week_number || 0);
  }
}
```

**Current Problem:**
The Column Settings table has too many columns (Column Name, Type, Category, 5+ role permission toggles, Actions) which causes horizontal overflow on standard desktop viewports (1280px). Users must scroll horizontally to see all permission toggles and actions.

**Root Cause Analysis:**
Likely causes:

1. Table uses `table-layout: fixed` with fixed column widths that don't adjust
2. Table container has `overflow-x-auto` class that enables scrolling
3. Permission toggle columns are too wide (each role gets a full column)
4. Parent container has constraints limiting table expansion

**Solution Approach:**

**Option 1: Flexible Table Layout (Recommended)**

```typescript
// Remove overflow-x-auto from container
<div className="w-full"> {/* Remove overflow-x-auto */}
  <Table className="w-full table-auto"> {/* table-auto instead of table-fixed */}
    {/* Columns with responsive widths */}
  </Table>
</div>

// Column width classes
- Column Name: className="min-w-[150px]" (flexible, grows to fill space)
- Type: className="w-20" (80px, fixed)
- Category: className="w-28" (112px, fixed)
- Permission toggles: className="w-24" per role (96px each, fixed)
- Actions: className="w-20" (80px, fixed)
```

**Option 2: Compact Permission Toggles**
If flexible layout still overflows, reduce permission column width:

- Use icon-only toggles (eye icon = view, pencil = edit) with tooltips
- Stack View/Edit toggles vertically within each cell
- Abbreviate role names in headers: "HR", "SDX", "ÖMC", "PAY", "TPX"

**Option 3: CSS Grid (Alternative)**

```typescript
<div className="grid grid-cols-[minmax(150px,1fr)_80px_120px_repeat(5,96px)_80px] w-full gap-2">
  {/* Grid cells for each column */}
</div>
```

**Testing Approach:**

1. Test at 1280px viewport (min desktop width) - most constrained
2. Test at 1440px and 1920px (common desktop sizes) - should have more space
3. Verify mobile card view (<768px) still works from Story 8.1
4. Use browser DevTools responsive mode for viewport testing

**Expected Result:**
At 1280px viewport width, all columns should be visible without horizontal scrolling. Permission toggles should be comfortably clickable. Table should expand to use available viewport width efficiently.
