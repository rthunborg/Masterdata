## User Story

**As a** developer maintaining the termination workflow system  
**I want** comprehensive automated tests for employee termination and reactivation  
**So that** I can ensure data integrity, spot management, and repayment tracking work correctly

---

## Context

Stories 8.13 and 8.14 implemented the termination and reactivation workflows with complex business rules:

**Termination (Story 8.14):**
1. Capture repayment data (ÖMC and PE3 date values)
2. Clear all date fields (stena, omc, pe3)
3. Release capacity spots for all dates
4. Update assigned_employees arrays
5. All operations in atomic transaction

**Reactivation (Story 8.13):**
1. Check spot availability for saved dates
2. Restore date values if spots available
3. Warn user if spots unavailable or dates deleted
4. Decrement spots and update arrays on restoration

**Current State**: ❌ No dedicated tests for termination/reactivation workflows

### Key Test Patterns

**Pattern 1: Termination Test**
```typescript
test('should save repayment dates and clear date fields on termination', async () => {
  const employee = await createTestEmployee({
    omc_date: '2025-03-08',
    pe3_date: '2025-04-20'
  });
  
  const result = await terminateEmployee(employee.id);
  
  expect(result.omc_repayment).toBe('2025-03-08');
  expect(result.pe3_repayment).toBe('2025-04-20');
  expect(result.omc_date).toBeNull();
  expect(result.pe3_date).toBeNull();
  expect(result.termination_date).toBe(today());
});
```

**Pattern 2: Spot Release Test**
```typescript
test('should release spots on termination', async () => {
  const date = await createTestDate({ remaining_spots: 10 });
  const employee = await createTestEmployee({ omc_date: date.date_value });
  
  // Spot decremented on assignment
  const dateAfterAssignment = await getDateById(date.id);
  expect(dateAfterAssignment.remaining_spots).toBe(9);
  
  // Terminate employee
  await terminateEmployee(employee.id);
  
  // Spot released
  const dateAfterTermination = await getDateById(date.id);
  expect(dateAfterTermination.remaining_spots).toBe(10);
});
```

**Pattern 3: Reactivation Warning Test**
```typescript
test('should warn when reactivating to unavailable date', async () => {
  const date = await createTestDate({ remaining_spots: 1 });
  const employee = await createTestEmployee({ omc_date: date.date_value });
  
  // Terminate
  await terminateEmployee(employee.id);
  
  // Another employee fills the spot
  await createTestEmployee({ omc_date: date.date_value });
  
  // Reactivate (spot no longer available)
  const result = await reactivateEmployee(employee.id);
  
  expect(result.restored_dates.omc).toBeNull();
  expect(result.warnings).toContainEqual(
    expect.objectContaining({
      date_type: 'ÖMC',
      reason: 'spot_unavailable'
    })
  );
});
```

**Pattern 4: Transaction Rollback Test**
```typescript
test('should rollback termination if spot release fails', async () => {
  const employee = await createTestEmployee({ omc_date: '2025-03-08' });
  
  // Mock database error during spot release
  vi.spyOn(supabase.rpc, 'release_date_capacity').mockRejectedValueOnce(
    new Error('DB Error')
  );
  
  await expect(terminateEmployee(employee.id)).rejects.toThrow();
  
  // Verify rollback: dates still assigned, repayment not saved
  const unchanged = await getEmployee(employee.id);
  expect(unchanged.omc_date).toBe('2025-03-08');
  expect(unchanged.omc_repayment).toBeNull();
  expect(unchanged.termination_date).toBeNull();
});
```

### Termination Workflow (Story 8.14)

```typescript
/**
 * Termination Workflow
 * 
 * 1. BEGIN TRANSACTION
 * 2. Read current date values (stena, omc, pe3)
 * 3. Save to repayment fields (omc_repayment, pe3_repayment)
 * 4. Clear date fields (stena_date=null, omc_date=null, pe3_date=null)
 * 5. For each assigned date:
 *    a. Call RPC: release_date_capacity(date_id, employee_id)
 *    b. Update assigned_employees array (remove employee_id)
 * 6. Set termination_date = today()
 * 7. COMMIT TRANSACTION
 * 
 * Rollback triggers:
 * - Any database error
 * - Constraint violation
 * - RPC function failure
 */
```

### Reactivation Workflow (Story 8.13)

```typescript
/**
 * Reactivation Workflow
 * 
 * 1. Read repayment fields (omc_repayment, pe3_repayment)
 * 2. For each repayment date:
 *    a. Check if date still exists
 *    b. Check if spots available (remaining_spots > 0)
 *    c. If both true: restore date, decrement spot, update array
 *    d. Else: add warning to response
 * 3. Clear termination_date
 * 4. Return: { restored_dates, warnings }
 * 
 * Warning reasons:
 * - 'spot_unavailable': Date full (remaining_spots = 0)
 * - 'date_deleted': Date no longer exists in important_dates
 */
```
