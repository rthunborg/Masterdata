## User Story

**As a** HR administrator managing ÖMC training dates  
**I want** the system to automatically assign hotel rooms to employees based on rank and gender  
**So that** room allocation follows business rules (CHEF gets private rooms, SEV shares by gender) and prevents violations

---

## Context

The ÖMC room assignment algorithm (FR40) was specified in Epic 8 but the implementation was missed. Story 11.2 has already created comprehensive test cases (52 tests) that define the expected behavior. This story implements the service and integrates it with the employee API routes.

**Current State**: 
- ❌ Room assignment service does not exist
- ❌ Database column `room_number_shared` does not exist
- ❌ No room assignment logic in employee creation/update flows
- ✅ Test suite exists (Story 11.2) with all acceptance criteria defined

**Business Rules (FR40):**
1. First employee for a date gets room 1
2. CHEF rank gets next available private room (incremented)
3. SEV rank shares room with same gender (max 2 per room)
4. SEV gets new room if no same-gender match or room full
5. Room recalculation when dates/hotels change

## Technical Notes

### Service Implementation Details

**File**: `src/lib/services/room-assignment.ts`

**Key Functions:**

1. **calculateRoomNumber()**
   - Input: employee data (omc_date, rank, gender, hotel_required)
   - Query existing employees for same omc_date with hotel_required=true
   - Apply FR40 algorithm
   - Return: room number (1-N) or null

2. **recalculateRoomsForDate()**
   - Input: ÖMC date ID
   - Get all employees for that date
   - Sort by rank (CHEF first), then hire_date
   - Recalculate all room assignments
   - Update database in transaction

3. **recalculateRoomsForEmployee()**
   - Input: employee ID, old date ID, new date ID
   - Recalculate rooms for old date (if exists)
   - Recalculate rooms for new date (if exists)
   - Update employee's room number

**Database Queries:**
```typescript
// Get existing employees for date
const { data: existingEmployees } = await supabase
  .from('employees')
  .select('id, rank, gender, room_number_shared, hire_date')
  .eq('omc_date', dateId)
  .eq('hotel_required', true)
  .not('room_number_shared', 'is', null)
  .order('rank', { ascending: false }) // CHEF first
  .order('hire_date', { ascending: true });
```

**Integration Points:**

1. **Employee Creation** (`POST /api/employees`):
   ```typescript
   // After validation, before repository.create()
   if (validatedData.omc_date && validatedData.hotel_required) {
     const roomNumber = await calculateRoomNumber({
       omc_date: validatedData.omc_date,
       rank: validatedData.rank,
       gender: validatedData.gender,
       hotel_required: true,
     }, supabase);
     
     normalizedData.room_number_shared = roomNumber;
   }
   ```

2. **Employee Update** (`PATCH /api/employees/[id]`):
   ```typescript
   // Detect changes
   if (updateData.omc_date !== existingEmployee.omc_date) {
     await recalculateRoomsForEmployee(
       employeeId,
       existingEmployee.omc_date,
       updateData.omc_date
     );
   }
   
   if (updateData.rank !== existingEmployee.rank ||
       updateData.gender !== existingEmployee.gender) {
     // Recalculate room for this employee
   }
   
   if (updateData.hotel_required === false) {
     updateData.room_number_shared = null;
   }
   ```

### Error Handling

- **Database errors**: Log and return null (no room assigned)
- **Concurrent updates**: Retry with exponential backoff
- **Invalid data**: Validate before calculation, return null if invalid
- **Transaction failures**: Rollback and return error to API

### Performance Considerations

- **Batch recalculation**: When recalculating for a date, do all employees in one transaction
- **Caching**: Consider caching room assignments for a date (optional optimization)
- **Indexing**: Ensure `omc_date` and `hotel_required` are indexed for fast queries
