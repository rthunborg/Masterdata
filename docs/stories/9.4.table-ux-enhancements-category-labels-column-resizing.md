## Story

## Acceptance Criteria

### AC 1: Category Label Display Below Column Headers

1. When a column has a category assigned, display the category name below the column header text
2. Category label text is displayed in a smaller font size than the column header (e.g., header: 14px, category: 11px)
3. Category label text is center-aligned within the column width
4. Category label appears in all table views: Dashboard, Important Dates, User Settings, Column Settings
5. If a column does not have a category assigned, no category label is displayed (no empty space)
6. Category label respects the category color if set (colored background with appropriate text contrast)
7. Visual hierarchy is clear: column header is primary, category label is secondary/subtle

### AC 2: Remove Category Color When Category is Unassigned

1. When a column's category is changed from a value to null/empty, the category color is automatically removed
2. Column header returns to standard/default styling (no background color)
3. Category color removal happens immediately (real-time update)
4. API endpoint `PATCH /api/admin/columns/[id]` supports setting `category_color: null` when `category` is set to null
5. Removal propagates to all table views within 2 seconds

### AC 3: Client-Side Column Width Resizing

1. Users can resize column width by dragging the column border/edge in the header
2. Column resizing works in all table views: Dashboard, Important Dates, User Settings, Column Settings
3. Resize cursor appears when hovering over column border
4. Minimum column width enforced (e.g., 80px) to prevent unusable narrow columns
5. Maximum column width enforced (e.g., 500px) to prevent excessive horizontal scrolling
6. Resizing is smooth and responsive without performance lag
7. Resizing one column does not automatically resize adjacent columns (independent sizing)

### AC 4: Column Width Persistence via Local Storage

1. Resized column widths are saved to browser `localStorage` immediately after resize
2. Saved widths persist across browser sessions (until cache/cookies are cleared)
3. Width preferences are stored per-user and per-table-view (e.g., Dashboard widths ≠ Column Settings widths)
4. If `localStorage` is unavailable or cleared, columns revert to default widths
5. No server-side database storage - purely client-side persistence
6. Storage key format: `columnWidths-{viewName}-{userId}` (e.g., `columnWidths-dashboard-user123`)

### AC 5: Column Width Reset Functionality

1. Provide a 'Reset Column Widths' button or option in table settings/toolbar
2. Clicking reset clears saved widths from `localStorage` and reverts columns to default widths
3. Reset applies only to the current table view (does not affect other views)
4. Visual confirmation provided after reset (e.g., toast notification)

### AC 6: Mobile Button Overflow Fixes

1. **Dashboard**: 'Add Employee' and 'Import Employee' buttons fit within screen width on mobile (no horizontal overflow)
2. **Important Dates View**: 'Add New Date' button fits within screen width on mobile (fully visible)

### Task 4: Create LocalStorage Utility for Column Width Persistence

**Subtasks:**

   - `getColumnWidthsStorageKey(viewName: string, userId: string): string`

2. Implement error handling for localStorage unavailability (e.g., Safari private mode)

4. Test utility functions with unit tests

**Files to Create:**

- `src/lib/utils/column-width-storage.ts`
- `src/lib/utils/column-width-storage.test.ts`

**Utility Example:**

```typescript
export function getColumnWidthsStorageKey(
  viewName: string,
  userId: string
): string {
  return `columnWidths-${viewName}-${userId}`;
}

export function saveColumnWidths(
  viewName: string,
  userId: string,
  widths: Record<string, number>
): void {
  try {
    const key = getColumnWidthsStorageKey(viewName, userId);
    localStorage.setItem(key, JSON.stringify(widths));
  } catch (error) {
    console.error('Failed to save column widths:', error);
  }
}

export function loadColumnWidths(
  viewName: string,
  userId: string
): Record<string, number> | null {
  try {
    const key = getColumnWidthsStorageKey(viewName, userId);
    const stored = localStorage.getItem(key);
    return stored ? JSON.parse(stored) : null;
  } catch (error) {
    console.error('Failed to load column widths:', error);
    return null;
  }
}

export function clearColumnWidths(viewName: string, userId: string): void {
  try {
    const key = getColumnWidthsStorageKey(viewName, userId);
    localStorage.removeItem(key);
  } catch (error) {
    console.error('Failed to clear column widths:', error);
  }
}
```

## Developer Notes

### TanStack Table Column Resizing Configuration

TanStack Table v8 provides built-in column resizing support. Key configuration options:

- **`columnResizeMode`**: Set to `'onChange'` for real-time resizing (default is `'onEnd'`)
- **`enableColumnResizing`**: Boolean to enable/disable resizing globally
- **`column.getCanResize()`**: Check if a specific column can be resized
- **`column.getSize()`**: Get current column width
- **`column.columnDef.minSize`**: Set minimum width (default 150px, we use 80px)
- **`column.columnDef.maxSize`**: Set maximum width (default 10000px, we use 500px)

**Example Table Configuration:**

```tsx
const table = useReactTable({
  data,
```

### LocalStorage Best Practices

**Storage Key Naming:**

- Use descriptive, namespaced keys: `columnWidths-{viewName}-{userId}`
- Avoid generic keys like `widths` to prevent collisions with other apps

**Error Handling:**

- Wrap all localStorage operations in `try-catch` blocks
- Handle `QuotaExceededError` (storage limit reached)
- Handle `SecurityError` (localStorage disabled, e.g., Safari private mode)

**Performance Considerations:**

- Debounce save operations (300ms delay) to avoid excessive writes during rapid resizing
- Use `JSON.stringify()` and `JSON.parse()` for complex objects
- Avoid storing large data structures (keep width objects small)

**Example Debounced Save:**

```tsx
const debouncedSave = useMemo(
  () =>
    debounce((widths: Record<string, number>) => {
      saveColumnWidths('dashboard', user.id, widths);
    }, 300),
  [user.id]
);

const table = useReactTable({

  onColumnSizingChange: (updater) => {
    const newSizing =
      typeof updater === 'function' ? updater(columnSizing) : updater;
    setColumnSizing(newSizing);
    debouncedSave(newSizing);
  },
});
```

### Mobile Responsive Design Strategy

**Breakpoints:**

- **Mobile (Small)**: 320px - 374px (iPhone SE, older Android)
- **Mobile (Standard)**: 375px - 767px (iPhone 12/13/14, Pixel)
- **Tablet**: 768px - 1023px (iPad, Android tablets)
- **Desktop**: 1024px+ (laptops, desktops)

**Button Layout Strategies:**

1. **Vertical Stacking**: Use `flex-col` on mobile, `flex-row` on desktop
2. **Reduced Padding**: Use smaller padding/gap on mobile (`gap-2` instead of `gap-4`)
3. **Font Size Adjustment**: Use `text-sm` on mobile, `text-base` on desktop
4. **Icon-Only Buttons**: Hide button text on mobile, show icon only (if space is tight)

**Touch Target Guidelines:**

- Minimum 44x44 pixels (iOS Human Interface Guidelines)
- Minimum 48x48 pixels (Android Material Design)
- Add padding to ensure touch targets meet minimum size even if visual button is smaller
