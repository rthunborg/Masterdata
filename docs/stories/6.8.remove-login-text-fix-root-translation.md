1. **Login Page:**
   - Remove text: "Ange dina uppgifter för att komma åt HR Masterdata-systemet" (Swedish)

### Investigation Notes: Root Page Issue

**Hypothesis 1: Missing Locale Landing Page**

The root page redirects to `/sv`, but there may be no `src/app/[locale]/page.tsx` file to render content at that route. This would cause Next.js to show a 404 or fallback behavior.

**Hypothesis 2: Middleware Configuration**

The `next-intl` middleware may be redirecting `/sv` elsewhere (e.g., to `/sv/dashboard` for authenticated users, `/sv/login` for unauthenticated users). This may be intentional behavior.

**Hypothesis 3: Story 5.13 Scope**

Story 5.13 (Complete Translation Coverage) may have addressed translation keys but not landing page content. Verify Story 5.13 implementation.

**Resolution Strategy:**

1. Check if `src/app/[locale]/page.tsx` exists
2. If missing, create it with Swedish landing page content
3. If exists, verify it uses correct translation keys
4. Test navigation flow: `/` → `/sv` → (landing page or redirect?)
5. Document actual vs expected behavior
6. Fix discrepancy

### Coding Standards Compliance

[Source: docs/architecture/coding-standards.md]

**Component Structure:**

- Use client components for interactive UI (`"use client"` directive)
- Use server components for static pages
- Import translations via `useTranslations()` hook (client) or `getTranslations()` (server)

**Translation Pattern:**

```tsx
import { useTranslations } from 'next-intl';

export default function MyComponent() {
  const t = useTranslations('namespace');

  return <div>{t('key')}</div>;
}
```

**File Naming:**

- Components: PascalCase (e.g., `LandingPage.tsx`)
- Pages: `page.tsx` (Next.js convention)
- Translation files: `sv.json`, `en.json` (lowercase locale codes)

### Known Issues and Edge Cases

**Edge Case 1: Authenticated User Landing**

- **Scenario:** User navigates to `/` while authenticated
- **Expected:** Redirect to `/sv/dashboard`
- **Current:** May show landing page briefly before redirect (handled by middleware)
- **Impact:** Minor UX issue, no functional problem

**Edge Case 2: Direct `/sv` Navigation**

- **Scenario:** User bookmarks or directly navigates to `/sv`
- **Expected:** Show landing page (unauthenticated) OR redirect to dashboard (authenticated)
- **Current:** Needs verification
- **Solution:** Middleware should handle authentication check and redirect appropriately

**Edge Case 3: Translation Key Deletion**

- **Scenario:** Removing `loginSubtitle` from translation files
- **Risk:** If any other component references this key, it will break
- **Mitigation:** Search codebase for `loginSubtitle` usage before deleting
- **Decision:** Leave translation keys in place (doesn't harm), only remove UI rendering

**Edge Case 4: Browser Back Button**

- **Scenario:** User clicks back after redirecting from `/` to `/sv`
- **Expected:** Stay on `/sv` or go to previous non-redirect page
- **Current:** Browser should handle correctly (redirect doesn't enter history)
- **Impact:** None if redirect uses `redirect()` from Next.js (doesn't add history entry)
