## B2: hasValueChanged Null/Undefined Bug (1 failure)

### Root Cause

The `hasValueChanged` function incorrectly treats `null` and `undefined` as equivalent when they should be considered different values.

**Current Implementation (lines 16-21):**
```typescript
if (original === null || original === undefined) {
  return current !== null && current !== undefined;
}
if (current === null || current === undefined) {
  return original !== null && original !== undefined;
}
```

**Problem:**
When `original = null` and `current = undefined`:
- Line 16: `original === null || original === undefined` → `true`
- Line 17: `current !== null && current !== undefined` → `true && false` → `false`
- Returns `false` (incorrect - should return `true`)

**Test Expectation:**
```typescript
expect(hasValueChanged(null, undefined)).toBe(true);
expect(hasValueChanged(undefined, null)).toBe(true);
```

**Related Epic 13 Story:** 13.10 (Prevent Unnecessary View Refreshes)

**Impact:**
- Change detection may miss changes when values transition between `null` and `undefined`
- Tests fail

**Fix Required:**
✅ **COMPLETE** - Update the null/undefined handling logic to treat them as different values:

```typescript
// Handle null/undefined cases - treat them as different values
if (original === null && current === undefined) return true;
if (original === undefined && current === null) return true;
if (original === null || original === undefined) {
  return current !== null && current !== undefined;
}
if (current === null || current === undefined) {
  return original !== null && original !== undefined;
}
```

**Status:** ✅ **FIXED** - The null/undefined handling has been implemented correctly at lines 19-26 of `change-detection.ts`.
