# Story 8.9: ÖMC Two-Day Date Format

## Status

**Approved**

---

## Story

**As an** HR Admin,
**I want** ÖMC dates to display as two-day ranges (e.g., "8-9th March"),
**So that** it reflects the actual two-day ÖMC training schedule.

---

## Acceptance Criteria

1. ÖMC date input accepts two-day range format (e.g., "8-9/3", "8-9th March")
2. Date picker for ÖMC dates allows selecting start and end date (must be consecutive days)
3. ÖMC dates display in format "8-9th March 2025" in important dates table
4. Validation ensures end date is exactly 1 day after start date (consecutive days only)
5. Database stores ÖMC dates as single date value (start date) with implicit +1 day for end
6. Employee assignment to ÖMC date references the full two-day range
7. Filtering and sorting by ÖMC date works correctly (sorts by start date)
8. CSV import supports two-day format parsing for ÖMC category
9. Export displays two-day format correctly (e.g., "8-9 mars" in Swedish)
10. Localization handles both English and Swedish date formats
11. Calendar views show ÖMC dates spanning two days visually
12. Validation prevents non-consecutive dates for ÖMC category

## Dev Notes

### Architecture Context

This story implements a specialized date format for ÖMC training dates, which span two consecutive days. The key architectural decision is to store only the start date in the database (as ISO string in `date_value`), with the end date being implicitly +1 day. This maintains database simplicity while supporting the two-day display format required by the business.

**Storage Strategy:**

- Database: Store start date as ISO string in `important_dates.date_value` column (no schema change needed)
- UI: Display as "8-9th March 2025" using formatting utilities
- Logic: Calculate end date = start date + 1 day (in-memory, not stored)

[Source: docs/epic-8-enhanced-employee-management-features.md#story-89]

  startDate: Date,

### Localization Requirements

**CRITICAL: Swedish-Only Application**

**Swedish (sv-SE) Format (REQUIRED):**

- Month names: "mars", "april", "maj", etc.
- Format: "8-9 mars 2025" (no ordinal suffix)
- This is the ONLY supported format

**Implementation:**

- Use `toLocaleDateString` with locale='sv-SE' (hardcoded)
- NO ordinal suffix (Swedish doesn't use ordinal suffixes for dates)
- Locale is ALWAYS 'sv-SE' - no dynamic locale switching
- Remove any references to English localization in implementation

- Previous documentation mentioned English locale support - this is deprecated
