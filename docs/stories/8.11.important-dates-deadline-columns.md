## Dev Notes

### Architecture Context

This story adds deadline enforcement to the important dates system, preventing employee date assignments after submission deadlines and preventing cancellations after cancellation deadlines. This is critical for operational workflows where training dates have strict enrollment and cancellation policies.

**Design Decision**: Store deadlines as separate DATE columns (`deadline_submit`, `deadline_cancel`) on the `important_dates` table. These deadlines are optional (nullable) and only apply to dates where enrollment/cancellation restrictions are needed.

**Business Rules:**

- `deadline_submit` must be <= `deadline_cancel` (submit deadline comes first)
- `deadline_cancel` must be <= `date_value` (cancel deadline must be before the event)
- After `deadline_submit` passes, no new employee assignments allowed
- After `deadline_cancel` passes, no employee unassignments (cancellations) allowed
- Deadlines are optional (can be null) - not all dates require deadline enforcement

### Database Schema

**Migration SQL:**

File: `migrations/YYYYMMDDHHMMSS_add_deadline_columns_to_important_dates.sql`

```sql
-- Add deadline columns to important_dates table
ALTER TABLE important_dates
ADD COLUMN deadline_cancel DATE,
ADD COLUMN deadline_submit DATE;

-- Add check constraints to enforce business rules
ALTER TABLE important_dates
ADD CONSTRAINT deadline_submit_before_cancel
CHECK (deadline_submit <= deadline_cancel OR deadline_submit IS NULL OR deadline_cancel IS NULL);

ALTER TABLE important_dates
ADD CONSTRAINT deadlines_before_date
CHECK (deadline_cancel <= date_value::date OR deadline_cancel IS NULL);

-- Add column comments for documentation
COMMENT ON COLUMN important_dates.deadline_submit IS 'Deadline for submitting new employee assignments. After this date, no new assignments allowed.';
COMMENT ON COLUMN important_dates.deadline_cancel IS 'Deadline for canceling employee assignments. After this date, no cancellations allowed.';

-- Verify columns and constraints added
SELECT column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_name = 'important_dates' AND column_name IN ('deadline_submit', 'deadline_cancel');

SELECT constraint_name, check_clause
FROM information_schema.check_constraints
WHERE constraint_name IN ('deadline_submit_before_cancel', 'deadlines_before_date');
```

**Column Details:**

- Type: DATE (PostgreSQL native date type)
- Nullable: YES (deadlines are optional)
- Default: NULL
- Constraints: Two CHECK constraints enforce business rules

**Employee Date Assignment Validation:**

Location: `src/lib/services/employee-service.ts` or API route
