## Context

On the dashboard, some employees’ SSN and hiring date fields show as `-` (empty/null) even though these values are present in the backend. This undermines trust in the dashboard and forces users to open detail views to verify data.

This story focuses on ensuring the correct values are displayed and that no-op edits do not trigger redundant updates or rerenders.

## User Story

As an HR user,  
I want SSN and hiring date to display correctly on the dashboard  
so that I can trust the overview without drilling into each employee.

## Scope / Notes

- Verify data flow from backend → API → UI model → rendered dashboard components for SSN and hiring date.
- Respect existing masking/formatting rules (e.g. SSN masking, date format).
- Ensure correct handling of **truly empty** values (only then show `-`).
- Ensure no-op edits (entering edit mode and leaving without change) do not send updates or trigger redundant rerenders.

## Acceptance Criteria

- **AC1 – Correct data mapping**  
  - Given an employee has SSN and hiring date populated in the backend  
  - When I open the dashboard  
  - Then the SSN and hiring date fields display the correct values (not `-`), formatted per our existing rules.

- **AC2 – Empty really means empty**  
  - Given an employee has no SSN and/or no hiring date in the backend  
  - When I open the dashboard  
  - Then the dashboard shows `-` (or our standard missing-value representation) only for those truly empty fields.

- **AC3 – No regressions for other employees**  
  - Given other employees with valid SSN/hiring dates  
  - When the dashboard loads  
  - Then their values remain correct and no new fields erroneously show as `-`.

- **AC4 – No-op edit does not cause updates or extra renders**  
  - Given I inline-edit SSN or hiring date  
  - And I leave the value unchanged (including leaving it empty if it was empty)  
  - When I exit edit mode  
  - Then no update is sent to the backend and the dashboard does not trigger redundant rerenders for that row/card.

- **AC5 – Dashboard tests updated and passing**  
  - When this story is completed  
  - Then dashboard tests are updated/added to cover SSN/hiring date display and no-op edit behavior  
  - And the dashboard test suite passes with no failures.
