- **Impact:**

  - E2E tests fail because they cannot verify non-functional features
  - This is a production bug, not just a test issue
- **Reproduction:**

  2. Attempt to edit a dropdown field (e.g., Gender) or boolean field
  3. Select a new value
  4. Observe that the value does not update or persist

## Playwright Testing Guide for Radix UI Select Components

**Key Principle:** Treat Radix `<Select>` like any other ARIA listbox, not like a native `<select>`. Don't use `page.selectOption()`. Open the trigger, click the option by role/name, and (if needed) add a small helper.

### How Radix Select Renders (Why It Can Be Confusing)

Radix `<Select>`:
- Does **not** render a native `<select>` element
- Renders a trigger (usually `<button>` or element with `role="combobox"`)
- Renders the options in a **portal at the end of `<body>`**:
  - List has `role="listbox"`
  - Items have `role="option"` and their text is the visible label

**This means:**
- `page.selectOption()` **doesn't work** (no real `<select>`)
- `mySelect.locator(...option...)` often fails, because the `<SelectItem>` is no longer inside the same DOM subtree (it's portaled to body)
- So we rely on accessible roles & names from the page root

### Basic Playwright Pattern

```typescript
// Open the select
const countrySelect = page.getByRole('combobox', { name: 'Country' });
await countrySelect.click();

// Click the option by its text label
await page.getByRole('option', { name: 'Sweden' }).click();

// Assert the selected value is shown in the trigger
await expect(countrySelect).toHaveText('Sweden');
```

If your trigger isn't exposed as `combobox` but as a `button`:

```typescript
const countryTrigger = page.getByRole('button', { name: 'Country' });
await countryTrigger.click();
await page.getByRole('option', { name: 'Sweden' }).click();
await expect(countryTrigger).toHaveText('Sweden');
```

### Don't Scope the Options to the Trigger Locator

Because of the portal, this **does not work**:

```typescript
const countrySelect = page.getByTestId('country-select');
await countrySelect.click();

// ❌ Radix content is not a descendant -> likely times out
await countrySelect.getByRole('option', { name: 'Sweden' }).click();
```

Instead, always search options from `page` (or via `getByRole('listbox')`):

```typescript
await page.getByRole('option', { name: 'Sweden' }).click();

// or, if you want to be explicit:
await page
  .getByRole('listbox')           // Radix Select.Content
  .getByRole('option', { name: 'Sweden' })
  .click();
```

### Helper Function for Reuse

If you have many selects, a helper keeps tests clean:

```typescript
// helpers/radixSelect.ts
import { Page, Locator, expect } from '@playwright/test';

export async function selectRadixOption(
  page: Page,
  trigger: Locator,
  optionLabel: string
) {
  await trigger.click();
  
  const option = page.getByRole('option', { name: optionLabel });
  await option.click();
  
  // Optional: assert it actually changed
  await expect(trigger).toContainText(optionLabel);
}
```

**Usage:**

```typescript
import { selectRadixOption } from './helpers/radixSelect';

test('selects a status', async ({ page }) => {
  const statusTrigger = page.getByTestId('status-select');
  
  await selectRadixOption(page, statusTrigger, 'Published');
});
```

### Stable Selectors: IDs, TestIDs, Labels

Best practices:

- Give the trigger something stable: `data-testid="country-select"`, then:
  ```typescript
  const countryTrigger = page.getByTestId('country-select');
  await selectRadixOption(page, countryTrigger, 'Sweden');
  ```

- Prefer accessible text for the option name (`name: 'Sweden'`) instead of internal Radix attributes like `data-radix-collection-item`.

- If you have multiple selects with the same options, you can disambiguate via the combobox label:
  ```typescript
  const billingCountry = page.getByRole('combobox', { name: /billing country/i });
  await billingCountry.click();
  await page.getByRole('option', { name: 'Sweden' }).click();
  ```

### Common Mistakes to Avoid

❌ **`page.selectOption('select[name="country"]', 'SE')`**
   - Radix doesn't use a real `<select>`; nothing happens.

❌ **Using CSS-only selectors like `.radix-SelectItem:nth-child(2)`**
   - Very brittle; breaks on reorder, filtering, translation, etc.

❌ **Scoping option lookup to the trigger locator (because of portals)**
   - Options are portaled to body, so they're not descendants of the trigger.
