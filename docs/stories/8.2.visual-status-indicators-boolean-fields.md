# Story 8.2: Visual Status Indicators for Boolean Fields

## Status

**Done**

## Story

**As an** HR Admin,  
**I want** boolean completion fields to show green badges when true,  
**so that** I can quickly scan employee completion status.

## Acceptance Criteria

1. The following fields display green badge when true: ISP, Photo, Origo, Mail, lön, Bankuppgifter, LI, Passport, Kvitto C17/18, C17
2. Badge displays "✓" checkmark icon with green background (`bg-green-100 text-green-800 border border-green-300`)
3. Badge appears inline next to field value in employee table
4. Badge does not display when field is false or null
5. Crewing/Done field displays green badge when true (additional logic in Story 8.5)
6. Badge is accessible with proper ARIA labels for screen readers (`aria-label="Completed"`)
7. Badge styling matches Stena Line design system colors
8. Mobile/responsive view displays badges with appropriate sizing
9. Print view includes badge status in readable format
10. Export to CSV includes boolean status as "Yes"/"No" or "Completed"/"Not Completed"
11. Visual consistency: all green badges use same styling
12. Performance: badge rendering doesn't degrade table performance with 1000+ rows

### Component Specifications

**StatusBadge Component:**

Location: `src/components/dashboard/status-badge.tsx`

Props:

- `status: 'green' | 'yellow' | null` - Badge color state
- `label?: string` - Optional accessibility label

Styling:

- Green badge: `bg-green-100 text-green-800 border border-green-300`
- Yellow badge: `bg-yellow-100 text-yellow-800 border border-yellow-300` (for Story 8.3)
- Icon: "✓" checkmark for green, "⚠" warning for yellow
- Size: `px-2 py-0.5` padding, `text-xs` font size
- Border: `border` with matching color
- Shape: `rounded` corners

```typescript
interface StatusBadgeProps {
  status: 'green' | 'yellow' | null;
  label?: string;
}

export function StatusBadge({ status, label }: StatusBadgeProps) {
  if (!status) return null;

  const styles = {
    green: 'bg-green-100 text-green-800 border-green-300',
    yellow: 'bg-yellow-100 text-yellow-800 border-yellow-300'
  };

  const ariaLabels = {
    green: 'Completed',
    yellow: 'Pending'
  };

  return (
    <span
      className={`inline-flex items-center px-2 py-0.5 rounded border text-xs font-medium status-badge ${styles[status]}`}
      aria-label={label || ariaLabels[status]}
    >
      {status === 'green' ? '✓' : '⚠'}
    </span>
  );
}
```

### Critical Findings

#### CRITICAL-001: Type Mismatch - Boolean Fields Are Actually TEXT

**Severity**: CRITICAL (Blocks Story Completion)

**Finding**:
The story assumes masterdata fields (`isps`, `photo`, `origo`, `mail_lon`, `lon`, `bankuppgifter`, `li`, `passport`, `kvitto_c17_18`, `c17`, `crewing_done`) are `boolean` type, but:

1. **Database Schema** (from `migrations/20251102000003_add_missing_masterdata_columns.sql`):

   ```sql
   ADD COLUMN isps TEXT,
   ADD COLUMN photo TEXT,
   ADD COLUMN origo TEXT,
   -- etc... ALL are TEXT type
   ```

2. **TypeScript Interface** (from `src/lib/types/employee.ts`):

   ```typescript
   export interface Employee {
     // ...
     isps: string | null; // NOT boolean!
     photo: string | null; // NOT boolean!
     origo: string | null; // NOT boolean!
     // ... all are string | null
   }
   ```

3. **Story Documentation** (from story Dev Notes):
   ```typescript
   // Story CLAIMS these exist as boolean:
   isps: boolean | null; // ISP completion
   photo: boolean | null; // Photo completion
   // But this is INCORRECT based on actual implementation
   ```

**Impact**:

- Acceptance Criteria 1-5 cannot be met because the fields don't have boolean values
- StatusBadge logic checking `value === true` will never trigger for TEXT fields
- Story 8.5 (Crewing/Done conditional logic) also depends on these being boolean
- Epic 8's entire vision assumes these are boolean completion tracking fields

**Evidence**:

- Database migration: `migrations/20251102000003_add_missing_masterdata_columns.sql` lines 10-21
- Type definition: `src/lib/types/employee.ts` lines 23-33
- Story 7.1 implementation chose TEXT type for flexibility

**Required Action**: Team decision needed before proceeding:

**Option A: Convert Fields to Boolean (Recommended for Epic 8 Vision)**

- Requires database migration to ALTER COLUMN types from TEXT to BOOLEAN
- Update TypeScript interfaces to use `boolean | null`
- Update validation schemas
- Data migration for existing TEXT values (if any)
- Risk: Breaking change if external parties have data in these fields
- Benefit: Aligns with Epic 8 vision and completion tracking use case

**Option B: Adapt Story to Work with TEXT Fields**

- Treat specific string values as "true" (e.g., "Yes", "Completed", "1", "true")
- Update StatusBadge integration to check string values
- Update acceptance criteria to reflect string-based logic
- Benefit: No breaking changes
- Risk: Less type-safe, requires string parsing logic, inconsistent with boolean field expectations

**Option C: Defer Story Until Type Refactoring (Recommended)**

- Add Story 8.0: "Refactor Masterdata Completion Fields to Boolean Type"
