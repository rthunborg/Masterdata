### Authorization Pattern

The app uses role-based access control with roles stored in `users` table:

- `hr_admin` - Full system access
- `omc`, `payroll`, `sodexo`, `toplux` - External party roles (dashboard access only)

**Standard Protection Pattern:**

```typescript
// Server component (page.tsx)
import { getCurrentUser } from '@/lib/auth';
import { redirect } from 'next/navigation';

export default async function ImportantDatesPage() {
  const user = await getCurrentUser();

  if (user.role !== 'hr_admin') {
    redirect('/');
  }

  // ... rest of component
}
```

### RLS Policy Pattern

Current RLS policies likely use this pattern:

```sql
-- Old (all authenticated users can read)
CREATE POLICY "Allow authenticated read important_dates"
ON important_dates FOR SELECT
TO authenticated
USING (true);

-- New (only hr_admin can read)
CREATE POLICY "Allow hr_admin read important_dates"
ON important_dates FOR SELECT
TO authenticated
USING (auth.jwt() ->> 'user_role' = 'hr_admin');
```

### Middleware Alternative

Instead of page-level checks, middleware can handle route protection:

```typescript
// middleware.ts
export function middleware(request: NextRequest) {
  const user = await getCurrentUser();
  const path = request.nextUrl.pathname;

  if (path.startsWith('/important-dates') && user.role !== 'hr_admin') {
    return NextResponse.redirect(new URL('/', request.url));
  }
}

export const config = {
  matcher: ['/important-dates/:path*', '/admin/:path*'],
};
```
