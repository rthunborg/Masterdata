# Story 7.6: Admin-Only Page Access Control

## Status

**Approved**

## Story

**As an** HR Admin,  
**I want** Important Dates page restricted to HR Admin access only,  
**so that** external parties cannot view or access internal operational planning data.

---

1. Important Dates page (`/dashboard/important-dates`) accessible only to HR Admin role
2. External parties (ÖMC, Payroll, Sodexo, Toplux) attempting to access `/dashboard/important-dates` are redirected to dashboard or receive 403 error
3. Important Dates navigation link hidden from external parties (only visible to HR Admin) - **CURRENTLY NOT IMPLEMENTED**
4. RLS policies updated to restrict important_dates table read/write access to hr_admin only
5. API endpoints (`/api/important-dates`) enforce hr_admin role check before processing requests
6. Middleware or page-level protection prevents unauthorized access attempts
7. User Settings and Column Settings pages remain HR Admin only (verify existing protection) - **ALREADY PROTECTED**
8. User Settings and Column Settings navigation links confirmed hidden from external parties (already implemented) - **ALREADY IMPLEMENTED**
9. All route protection works correctly with session-based authentication
10. Error messages are user-friendly (e.g., "Access denied: This page is restricted to administrators")
11. Manual testing confirms external party users cannot access restricted pages through direct URL navigation
12. **NEW**: User creation works (fix RLS policies blocking user creation)
13. **NEW**: Delete user button added alongside inactivate button
14. **NEW**: HR Admin cannot delete or inactivate other HR Admin accounts if only 1 active HR admin remains

### Authorization Pattern

The app uses role-based access control with roles stored in `users` table:

- `hr_admin` - Full system access
- `omc`, `payroll`, `sodexo`, `toplux` - External party roles (dashboard access only)

**Standard Protection Pattern:**

```typescript
// Server component (page.tsx)
import { getCurrentUser } from '@/lib/auth';
import { redirect } from 'next/navigation';

export default async function ImportantDatesPage() {
  const user = await getCurrentUser();

  if (user.role !== 'hr_admin') {
    redirect('/');
  }

  // ... rest of component
}
```

### RLS Policy Pattern

Current RLS policies likely use this pattern:

```sql
-- Old (all authenticated users can read)
CREATE POLICY "Allow authenticated read important_dates"
ON important_dates FOR SELECT
TO authenticated
USING (true);

-- New (only hr_admin can read)
CREATE POLICY "Allow hr_admin read important_dates"
ON important_dates FOR SELECT
TO authenticated
USING (auth.jwt() ->> 'user_role' = 'hr_admin');
```

### Middleware Alternative

Instead of page-level checks, middleware can handle route protection:

```typescript
// middleware.ts
export function middleware(request: NextRequest) {
  const user = await getCurrentUser();
  const path = request.nextUrl.pathname;

  if (path.startsWith('/important-dates') && user.role !== 'hr_admin') {
    return NextResponse.redirect(new URL('/', request.url));
  }
}

export const config = {
  matcher: ['/important-dates/:path*', '/admin/:path*'],
};
```
