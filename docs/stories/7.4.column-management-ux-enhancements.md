# Story 7.4: Column Management UX Enhancements

## Status

**Approved**

---

## Story

**As an** HR Admin,  
**I want** improved column management interface with inline visibility editing and column creation,  
**so that** I can efficiently configure column permissions without cumbersome modals.

---

## Acceptance Criteria

1. Column Settings page includes prominent "Create New Column" button visible to HR Admin
2. "Create New Column" button opens modal/form to create custom columns (masterdata columns managed via migrations)
3. "Show" button removed from Column Settings table
4. Visibility column displays inline editable toggles/dropdowns for each role (HR Admin, Sodexo, ÖMC, Payroll, Toplux)
5. Clicking visibility toggle updates permissions immediately via API call
6. Visual feedback shows save state (loading spinner, success checkmark)
7. Validation prevents invalid states: Edit permission requires View permission, HR Admin cannot remove own View permission
8. Inline editing works with keyboard navigation (Tab, Enter, Escape)
9. Permissions changes reflected in preview mode and external party views immediately
10. Error handling displays clear messages if permission update fails
11. Only HR Admin can access Column Settings page (external parties have no access to admin functions)
12. HR Admin can edit all column permissions for all roles

## Dev Notes

### Component Architecture

New components needed:

1. **CreateColumnModal**: Form for creating custom columns
2. **InlinePermissionEditor**: Inline editable permission checkboxes for each role

### Permission Editing Rules

**HR Admin Capabilities:**

- Can edit View and Edit permissions for ALL roles (hr_admin, omc, payroll, sodexo, toplux)
- Can edit permissions for BOTH masterdata and custom columns
- HR Admin's own View permission is locked (always true, checkbox disabled)
- HR Admin's Edit permission can be modified if needed

**External Party Access:**

- External parties (ÖMC, Payroll, Sodexo, Toplux) have NO access to Column Settings page
- Only HR Admin role can access `/admin/columns` route
- Route protection via middleware or role check in page component

**Validation Rules:**

1. Edit permission requires View permission (if Edit is checked, View must be checked)
2. If View is unchecked, Edit is automatically unchecked
3. HR Admin View permission cannot be unchecked (validation prevents this)

` ypescript
type RolePermissions = {
[roleName: string]: {
view: boolean;
edit: boolean;
};
};

// Example:
const permissions: RolePermissions = {
hr_admin: { view: true, edit: true },
omc: { view: true, edit: false },
payroll: { view: false, edit: false },
sodexo: { view: true, edit: false },
toplux: { view: false, edit: false }
};
`

### API Endpoints

- **POST /api/columns**: Create new custom column
  - Body: { column_name, column_type, category }
  - Response: Created column config
- **PATCH /api/columns/[id]**: Update column permissions
  - Body: { role_permissions: RolePermissions }
  - Response: Updated column config

### Visual Design

| Column Name | Type | Category    | HR Admin | ÖMC | Payroll | Sodexo | Toplux | Actions |

**Legend**: V = View, E = Edit, = Checked, = Unchecked
