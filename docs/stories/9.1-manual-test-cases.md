# Manual Test Cases: Story 9.1 - Category Color Coding

## Overview

This document provides step-by-step manual test cases for the Category Color Coding feature. Each test case includes preconditions, steps, and expected results.

**Test Environment:** Local development or staging  
**Browser Compatibility:** Chrome, Firefox, Safari, Edge  
**User Roles:** HR Admin, External Party User  
**Story:** 9.1 - Category Color Coding for Column Headers

---

## Test Case 1: Create Column with Category Color

**Objective:** Verify users can assign a color to a category when creating a new custom column.

**Preconditions:**

- User is logged in as HR Admin
- User has access to the Add Column Modal

**Steps:**

1. Navigate to Dashboard
2. Click "Add Column" button
3. Enter column name: "Team Assignment"
4. Select column type: "Text"
5. Enter new category name: "Recruitment"
6. Observe color picker appears below category field
7. Click a predefined color (e.g., Blue #3B82F6)
8. Verify color preview shows selected color
9. Click "Add Column" to submit

**Expected Results:**

- Color picker appears when new category name is entered
- Predefined color palette shows 10 colors
- Color preview updates to show selected color with "Sample Text"
- Column is created successfully
- Table header for "Team Assignment" shows blue background
- Header text is black (readable on blue background)
- Tooltip on header shows "Recruitment (#3B82F6)"

**Pass Criteria:** All expected results met

## Test Case 3: Invalid Hex Color Validation

**Objective:** Verify color picker validates hex format.

**Preconditions:**

- Add Column Modal open with category entered

**Steps:**

1. Enter category name: "Test Category"
2. Open color picker
3. Enter invalid hex: "invalid"
4. Observe error message
5. Enter invalid hex: "123" (missing #)
6. Observe error message
7. Enter valid hex: "#3B82F6"
8. Verify error clears

**Expected Results:**

- Error message: "Invalid hex color format (use #RGB or #RRGGBB)"
- Error displays in red text below input
- Form submission prevented with invalid hex
- Error clears when valid hex entered
- Predefined color selection clears error

**Pass Criteria:** Validation prevents invalid colors

---

## Test Case 4: Color Contrast Warning

**Objective:** Verify system warns about poor contrast colors.

**Preconditions:**

- Add Column Modal open

**Steps:**

1. Enter category: "Light Category"
2. Open color picker
3. Enter very light color: "#FFFF00" (bright yellow)
4. Observe warning message (if triggered)
5. Try very dark color: "#0000FF" (pure blue)
6. Observe whether warning appears

**Expected Results:**

- Warning appears for colors with poor contrast: "This color may have poor contrast. Consider a lighter or darker shade."
- Warning shown in yellow text with ⚠ icon
- Warning does not prevent form submission (is advisory only)
- All predefined palette colors should NOT trigger warning

**Pass Criteria:** Warning system helps guide accessible color choices

## Test Case 9: Keyboard Navigation in Color Picker

**Objective:** Verify color picker is keyboard accessible.

**Preconditions:**

- Add Column Modal open with category entered

**Steps:**

1. Use Tab key to focus color picker trigger button
2. Press Enter or Space to open popover
3. Use Tab to navigate through predefined color buttons
4. Press Enter to select a color
5. Tab to custom color input
6. Enter hex value with keyboard
7. Tab to "Clear" and "Done" buttons

**Expected Results:**

- All interactive elements receive focus outline
- Tab order is logical (predefined colors → custom input → actions)
- Enter/Space keys activate buttons
- Focus trap keeps focus within popover when open
- Escape key closes popover

**Pass Criteria:** Full keyboard navigation supported
