## Context

The project has accumulated a comprehensive test suite over multiple stories:

**Test Suite Overview:**
- **Unit Tests**: ~150+ tests (services, utils, components, hooks)
- **Integration Tests**: ~200+ tests (API routes, workflows, constraints)
- **E2E Tests**: 9 test files (Playwright)
- **Performance Tests**: 10+ benchmark files

**Current Concerns:**
- Tests may have been written for older architecture patterns
- Some tests may be failing due to code changes
- Outdated tests may reference removed features or changed APIs
- Test setup/teardown may need updates for current database schema
- Mock data may not match current data models

**Impact:**
- Failing tests reduce confidence in the test suite
- Outdated tests provide false sense of security
- Broken tests slow down development workflow
- Inconsistent test patterns make maintenance difficult

## Risks & Mitigations

### Risk 1: Large Number of Failing Tests
**Risk**: Test suite has many failures, making fix work overwhelming.

**Mitigation**:
- Prioritize critical tests first (business logic, API routes)
- Fix tests in batches by category
- Document patterns for similar fixes
- Consider splitting into multiple PRs if needed

### Risk 2: Unclear Test Intent
**Risk**: Outdated tests have unclear purpose, making it hard to decide fix vs. remove.

**Mitigation**:
- Review related code/stories for context
- Check git history for test origins
- Consult with team on test importance
- When in doubt, update rather than remove

### Risk 3: Architecture Changes Too Extensive
**Risk**: Some tests require major rewrites due to significant architecture changes.

**Mitigation**:
- Identify tests needing major updates
- Prioritize high-value tests
- Consider creating new tests if rewrite is too extensive
- Document architectural changes in test comments

### Risk 4: Flaky Tests
**Risk**: Some tests are flaky (intermittent failures), making validation difficult.

**Mitigation**:
- Run test suite multiple times to identify flakiness
- Fix timing issues, race conditions
- Add proper wait/retry logic
- Mock external dependencies consistently
