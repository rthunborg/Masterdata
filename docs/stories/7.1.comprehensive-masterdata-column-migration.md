## Story

**As an** HR Admin,  
**I want** all required masterdata columns configured with correct external party visibility permissions,  
**so that** external parties see exactly the columns they need for their workflows.

## Acceptance Criteria

1. Database migration creates/updates 23 masterdata columns: Stena Date, ÖMC Date, PE3 Date, First Name, Surname, Town district, Mobile, Email, Social Security No., Rank, Gender, Comments, One, ISPS, Photo, Origo, Lönenivå, Mail lön, Bankuppgifter, LI, Passport, Kvitto C17/18, C17, Crewing/Done
2. Column configuration seeded with correct role permissions per external party:
   - **ÖMC Masterdata (view-only):** ÖMC Date, Name (First Name + Surname), Social Security No., Contact No. (Mobile), Email, Rank, Gender
   - **Payroll Masterdata (view-only):** Stena Date, Förnamn (First Name), Efternamn (Surname), Personnummer (SSN), Telnr (Mobile), Mail (Email), Titel (Rank)
   - **Sodexo Masterdata (view-only):** Stena Date, Deltagare (Name = First Name + Surname)
   - **Toplux Masterdata (view-only):** Stena Date, Förnamn, Efternamn, Personnummer, Telnr, Mail, Ort (Town district), Titel
3. HR Admin can view all 23 columns with full edit permissions
4. Employee table displays columns in correct order as specified in feedback
5. Missing columns (currently not in employees table) added to schema: One, ISPS, Photo, Origo, Lönenivå, Mail lön, Bankuppgifter, LI, Passport, Kvitto C17/18, C17, Crewing/Done
6. Display order configuration stored and enforced in column_config table
7. Column types correctly defined (text, date, boolean, etc.)
8. Existing employee records maintain data integrity (nulls for new columns)
9. Real-time sync works correctly with expanded column set
10. Performance acceptable with 23 columns (table render <2s for 1,000 employees)
