# Story 9.5: UI Polish - Column Settings & Dashboard Fixes

## Status

**Ready for Review**

## Story

**As a** HR Admin,  
**I want** improved UI clarity and consistency in column settings and dashboard views,  
**so that** the interface is more intuitive, visually aligned, and displays data correctly.

---

## Acceptance Criteria

### AC 1: Column Settings - Display Both Column Names with Edit Control

1. In column settings table, both `column_name` (display name) and `db_column_name` (database name) are visible
2. Users can edit `column_name` but `db_column_name` is read-only/non-editable
3. Clear visual distinction between editable and non-editable column name fields
4. Changes to `column_name` persist to database correctly

### AC 2: Column Settings - Simplify Category Color Display

1. Remove duplicate color indicator that appears before category name value
2. Keep single color indicator in appropriate location (inline with category dropdown or as separate color picker button)
3. Category selection dropdown still shows color indicators for existing categories
4. No loss of functionality - users can still assign/change category colors

### AC 3: Column Settings - Improve Activate/Deactivate Button Styling

1. Activate/Deactivate (Eye/EyeOff) button has a small rounded border around it
2. Border is subtle but visible (e.g., `border border-gray-300 rounded`)
3. Gap/margin added between button border and surrounding elements for better visual separation
4. Button remains functionally the same (toggles visibility)

### AC 4: Dashboard - Harmonize Category Display in Column Headers

1. All columns with categories show category name consistently (either above header, below header, or both - must be uniform)
2. Remove inconsistent spacing/gaps where category appears below header only
3. Visual alignment is consistent across all categorized columns
4. Non-categorized columns remain unchanged

### AC 5: Dashboard - Fix Date Value Display (Show Description Not GUID)

1. Date columns (Stena Date, ÖMC Date, PE3 Date) display `date_description` instead of GUID
2. Date description format matches important dates table format (e.g., "Week 45 - Planning Meeting")
3. Null/empty date values display appropriately (empty or placeholder)
4. Date editing functionality remains intact

### AC 6: All Views - Center-Align Column Headers with Column Data

1. Column headers (`TableHead`) are horizontally center-aligned with column data cells
2. Applies to all table views: Dashboard, Important Dates, User Management, Column Settings
3. Both header text and data values align consistently
4. Maintains readability and visual harmony

### Key Technical Context

1. **Column Names**: The system has two name fields:
   - `column_name`: User-facing display name (editable, updates propagate to dashboard headers)
   - `db_column_name`: Database field name (read-only, system-generated, used for data access)

2. **Column Config to Employee Table Connection**:
   - Employee table uses `useColumns()` hook to fetch column configurations from `column_config` table
   - Each `ColumnConfig` defines display properties: `column_name` (header text), `db_column_name` (data field), `category`, `category_color`, permissions
   - Employee table dynamically generates columns from `columnConfigs` array (see employee-table.tsx line 352+)
   - Real-time updates: Changes to `column_config` trigger automatic refresh via `useRealtime` hook
   - When `column_name` is updated, dashboard headers will auto-refresh to show new name

3. **Category Colors**: Currently displayed in `EditableCategoryCell` component with TWO `ColorIndicator` instances:
   - One inside the dropdown button (line ~127) showing current color - **REMOVE THIS ONE**
   - One as separate color picker button to the right - **KEEP THIS ONE**
   - Additional indicators in dropdown list items - **KEEP THESE**

4. **Date Display**: Date columns store GUID references to `important_dates` table. The `getEmployeeFieldValue` function should resolve these to `date_description` using `resolveImportantDateId` utility.

5. **Column Header Alignment**: The `TableHead` component in `ui/table.tsx` currently has `text-center` class, but there may be overrides in specific table implementations causing misalignment.

6. **Category Display Pattern**: Story 9.4 implemented category labels below headers. Need to ensure this pattern is consistent and remove any duplicate category displays or excessive spacing.

### Important Dates Context

The `ImportantDate` interface includes:

- `id`: UUID
- `date_description`: Human-readable description (e.g., "Week 45 - Planning")
- `date_value`: Actual date value
- `category`: Category grouping

Date columns in employee records store the `id` (GUID), which must be resolved to `date_description` for display.

### Component Hierarchy

- **Column Settings**: `column-settings-table.tsx` → `EditableCategoryCell` → `ColorPicker` / `ColorIndicator`
- **Dashboard**: `employee-table.tsx` → uses `useColumns()` hook → renders headers from `column_name` field
- **Dashboard Data**: `employee-table.tsx` → `EditableDateCell` → displays date value
- **Table Base**: All tables use `src/components/ui/table.tsx` for `TableHead`, `TableCell` components

### API Endpoint Update Required

**PATCH `/api/admin/columns/[id]`** (src/app/api/admin/columns/[id]/route.ts)

- Currently accepts: `role_permissions`, `category`, `category_color`
- **Need to add**: `column_name` field to updateColumnConfigSchema validation and update logic
- **Validation**: Ensure `column_name` is non-empty string, trim whitespace
- **Note**: `db_column_name` should NOT be editable via API (system-managed field)
