# Story 9.1: Category Color Coding for Column Headers

## Status

**Approved**

---

## Story

**As an** external party user or HR Admin,  
**I want** to assign colors to custom column categories and see those colors reflected in the table column headers,  
**so that** I can visually distinguish between different category groups at a glance and improve data organization clarity.

---

## Acceptance Criteria

### AC 1: Database Schema for Category Colors

1. `column_config` table supports storing category color metadata
2. Color storage supports hex color codes (e.g., `#3B82F6`) or predefined color names
3. Multiple columns can share the same category and inherit the same color
4. Migration script updates existing schema without data loss
5. Default/null color value results in no background coloring (standard header appearance)

### AC 2: Color Selection UI in Add Column Modal

1. Add Column Modal includes color picker/selector for category color when creating new category
2. Color picker appears when user types a new category name (not in existing categories list)
3. Color picker offers predefined color palette (minimum 8-10 colors) for quick selection
4. Color picker allows custom hex color input for advanced users
5. Selected color is displayed as preview next to category input field
6. Selecting existing category automatically shows that category's assigned color
7. Color selection is optional - user can create category without color (defaults to no color)

### AC 3: Color Selection UI in Column Settings (Inline Edit)

1. EditableCategoryCell in Column Settings Table shows current category color indicator
2. When dropdown opens for category selection, existing categories display color swatches
3. User can change category color when editing category assignment inline
4. Color changes to category affect all columns sharing that category immediately
5. Color picker/selector UI is consistent with Add Column Modal design

### AC 4: Color Selection UI in Create Column View

1. Create Column view (if separate from Add Column Modal) supports category color selection
2. Color selection workflow matches Add Column Modal pattern
3. Color preview updates in real-time as user selects color
4. Form validation allows null/empty color value

### AC 5: Column Header Background Coloring in Dashboard

1. Table column headers display background color when category has assigned color
2. Color is applied as background fill with sufficient contrast for header text (white or dark text based on luminance)
3. Header text remains legible on all color backgrounds (accessibility contrast ratio ≥ 4.5:1)
4. Color intensity is subtle enough not to overwhelm the interface (consider using opacity or lighter tints)
5. Masterdata columns (Employee Information category) do not show category colors by default
6. Only custom columns with categorized colors display colored headers
7. Columns without category or with categories without colors show standard header styling

### AC 6: Color Management and Persistence

1. Category color changes are persisted to database via API
2. Color updates propagate to all columns sharing that category within 2 seconds
3. Color changes trigger table re-render to update header styling
4. API endpoint supports updating category color: `PATCH /api/admin/categories/{categoryName}`
5. Authorization checks ensure only users with permission can modify category colors

### AC 7: UX and Visual Design Consistency

1. Color picker component follows existing design system (shadcn/ui patterns)
2. Color swatches in dropdowns are sized appropriately (min 16x16px for accessibility)
3. Color preview indicators are visible and intuitive
4. Tooltip on colored header shows category name and color code
5. Color selection interface is mobile-responsive
6. Swedish translations provided for all new UI text (color labels, tooltips, etc.)

### AC 8: Performance and Compatibility

1. Adding category colors does not degrade table rendering performance (maintains <2s load time)
2. Color styling works across supported browsers (Chrome, Firefox, Edge, Safari - last 2 versions)
3. Color selection UI is keyboard accessible (tab navigation, enter to select)
4. Screen readers announce category color information appropriately

### AC 9: Testing Coverage

1. Unit tests verify color storage in database schema
2. Unit tests validate color picker component functionality
3. Integration tests verify color persistence via API
4. E2E/manual tests confirm colored headers render correctly in dashboard
5. Accessibility tests verify contrast ratios meet WCAG AA standards

## Dev Notes

### Database Schema Considerations

**Option 1: Add Color Field to column_config**

```sql
ALTER TABLE public.column_config
ADD COLUMN category_color TEXT DEFAULT NULL;
```

- **Pros:** Simple, minimal schema change
- **Cons:** Duplicate color storage if multiple columns share category (data denormalization)

**Option 2: Create Separate categories Table**

```sql
CREATE TABLE IF NOT EXISTS public.categories (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  name TEXT NOT NULL UNIQUE,
  color TEXT DEFAULT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Add foreign key relationship
ALTER TABLE public.column_config
ADD COLUMN category_id UUID REFERENCES public.categories(id);
```

- **Pros:** Normalized data model, single source of truth for category colors, easier to manage category metadata
- **Cons:** Requires migration of existing category strings to category references, more complex queries

**Recommendation:** **Option 2 (Separate categories table)** provides better data integrity and scalability for future category-related features (e.g., icons, descriptions). However, given the current simplicity and MVP focus, **Option 1** may be more pragmatic for initial implementation. Consider starting with Option 1 and refactoring to Option 2 if category management becomes more complex.

### Color Contrast Utility Function

[Source: WCAG Accessibility Guidelines]

```typescript
// src/lib/utils/color-contrast.ts

/**
 * Calculate relative luminance of RGB color
 * Reference: WCAG 2.1 - https://www.w3.org/TR/WCAG21/#dfn-relative-luminance
 */
function getLuminance(r: number, g: number, b: number): number {
  const [rs, gs, bs] = [r, g, b].map((c) => {
    const val = c / 255;
    return val <= 0.03928 ? val / 12.92 : Math.pow((val + 0.055) / 1.055, 2.4);
  });
  return 0.2126 * rs + 0.7152 * gs + 0.0722 * bs;
}

/**
 * Convert hex color to RGB values
 */
function hexToRgb(hex: string): { r: number; g: number; b: number } | null {
  const result = /^#?([a-f\d]{2})([a-f\d]{2})([a-f\d]{2})$/i.exec(hex);
  return result
    ? {
        r: parseInt(result[1], 16),
        g: parseInt(result[2], 16),
        b: parseInt(result[3], 16),
      }
    : null;
}

/**
 * Calculate contrast ratio between two colors
 * Reference: WCAG 2.1 - https://www.w3.org/TR/WCAG21/#dfn-contrast-ratio
 */
export function getContrastRatio(color1: string, color2: string): number {
  const rgb1 = hexToRgb(color1);
  const rgb2 = hexToRgb(color2);

  if (!rgb1 || !rgb2) return 0;

  const lum1 = getLuminance(rgb1.r, rgb1.g, rgb1.b);
  const lum2 = getLuminance(rgb2.r, rgb2.g, rgb2.b);

  const lighter = Math.max(lum1, lum2);
  const darker = Math.min(lum1, lum2);

  return (lighter + 0.05) / (darker + 0.05);
}

/**
 * Determine if white or black text should be used on given background color
 * Returns "white" or "black" based on WCAG contrast requirements
 */
export function getReadableTextColor(
  backgroundColor: string
): 'white' | 'black' {
  const whiteContrast = getContrastRatio(backgroundColor, '#FFFFFF');
  const blackContrast = getContrastRatio(backgroundColor, '#000000');

  // WCAG AA requires 4.5:1 for normal text
  // Use white text if it has better contrast, otherwise use black
  return whiteContrast >= blackContrast ? 'white' : 'black';
}

/**
 * Check if color combination meets WCAG AA contrast requirements
 */
export function meetsContrastRequirement(
  textColor: string,
  backgroundColor: string,
  level: 'AA' | 'AAA' = 'AA'
): boolean {
  const contrast = getContrastRatio(textColor, backgroundColor);
  const required = level === 'AAA' ? 7 : 4.5;
  return contrast >= required;
}
```

### API Endpoint Design

**Approach 1: Extend Existing Column Update Endpoint**

```typescript
// PATCH /api/admin/columns/{id}
// Request body includes category_color field
{
  "column_name": "Team Assignment",
  "category": "Recruitment Team",
  "category_color": "#3B82F6"
}
```

- **Pros:** Reuses existing authorization and validation logic
- **Cons:** Category color update affects multiple columns, requires updating all columns with same category

**Approach 2: Create Dedicated Category Update Endpoint**

```typescript
// PATCH /api/admin/categories/{categoryName}
// Request body
{
  "color": "#3B82F6"
}

// Response
{
  "data": {
    "category": "Recruitment Team",
    "color": "#3B82F6",
    "affected_columns": ["col-1", "col-2", "col-3"]
  }
}
```

- **Pros:** Single update affects all columns in category, clearer intent
- **Cons:** New endpoint to maintain

**Recommendation:** **Approach 2** is cleaner for category-wide color changes. However, if using Option 1 database schema (denormalized), may need to update multiple column records.

### Accessibility Considerations

1. **Color Blindness:** Ensure colors are distinguishable for color-blind users (use sufficient saturation differences)
2. **Contrast Ratios:** Enforce WCAG AA contrast (≥4.5:1) between text and background
3. **Keyboard Navigation:** Color picker must be fully keyboard accessible (Tab, Enter, Arrow keys)
4. **Screen Readers:** Announce color selection changes and category color information
5. **Focus Indicators:** Visible focus states on color swatches

### Performance Considerations

- **Color Calculation:** Color contrast calculations should be memoized to avoid repeated processing
- **Table Rendering:** Applying background colors to headers should not trigger unnecessary re-renders
- **API Calls:** Batch color updates if changing multiple categories simultaneously
- **CSS Approach:** Use inline styles or CSS variables for dynamic color application (avoid generating new CSS classes per color)
