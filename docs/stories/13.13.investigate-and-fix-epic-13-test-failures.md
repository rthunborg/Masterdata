## Technical Notes

### Test Organization

All tests related to Epic 13 should be organized in:
- Unit tests: `tests/unit/epic-13/story-13.X/`
- Integration tests: `tests/integration/epic-13/story-13.X/`
- E2E tests: `tests/e2e/epic-13/story-13.X/`

### Investigation Approach

1. **Start with test output**: Read error messages carefully
2. **Trace to code**: Find the code being tested and the Epic 13 changes
3. **Compare behavior**: Compare old vs. new expected behavior
4. **Verify requirements**: Check if new behavior matches Epic 13 story requirements
5. **Determine fix**: Fix implementation if bug, fix test if scope changed

### Common Failure Patterns to Look For

1. **Selection-related failures**: Tests may expect old selection behavior
2. **Export-related failures**: Tests may not account for new field selection or selected-employee-only export
3. **Filter-related failures**: Tests may expect old filter behavior
4. **Visual indicator failures**: Tests may not account for new status tints
5. **Header text failures**: Tests may expect "HR Masterdata" instead of "Säsongsrekrytering 2026"
6. **Refresh behavior failures**: Tests may expect old refresh behavior

### Decision Framework

**When determining if a failure is Type A (scope change) vs. Type B (bug):**

- **Type A (Scope Change)** if:
  - New behavior matches Epic 13 story requirements
  - Old test expectation conflicts with new requirements
  - Implementation correctly implements new requirements
  - Test needs updating to match new requirements

- **Type B (Bug)** if:
  - New behavior doesn't match Epic 13 story requirements
  - Implementation has logic errors or edge cases not handled
  - Test expectation is correct but implementation is wrong
  - Fix requires changing implementation, not test
