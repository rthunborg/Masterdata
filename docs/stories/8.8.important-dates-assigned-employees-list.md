# Story 8.8: Important Dates Assigned Employees List

## Status

**Done**

---

## Story

**As an** HR Admin,  
**I want** to see which employees are assigned to each date,  
**So that** I can review assignments, contact employees if needed, and manage capacity effectively.

---

## Acceptance Criteria

1. Database adds `assigned_employees` JSONB column to `important_dates` table
2. When employee is assigned to a date, add employee ID and name to `assigned_employees` JSONB array
3. When employee's date is removed, remove employee from `assigned_employees` array
4. Important Dates table displays "Assigned Employees" column showing employee count badge (e.g., "15")
5. Click on employee count opens modal/popover with full list of assigned employee names
6. Modal includes employee details: Name, Email, SSN (last 4 digits), Room Number (if applicable)
7. Export includes full list of assigned employees per date in readable format
8. Sorting by number of assigned employees works correctly
9. Real-time updates: when employees are assigned/unassigned, list updates immediately
10. Performance optimized for dates with many assigned employees (>50, use pagination in modal)
11. Search functionality within assigned employees modal
12. Option to download assigned employees list as CSV for specific date (single date view)
13. Option to export CSV of all employees assigned to dates within a specific category (Stena/ÖMC/PE3)
14. Category export includes date range filter: only include employees assigned to dates within the selected date range
15. Category export allows user to select which employee fields to include in export
16. Field selection shows only non-boolean masterdata fields (e.g., First Name, Surname, SSN, Email, Mobile, Rank, Gender, Town District, Hire Date, Stena Date, ÖMC Date, PE3 Date, Room Number)
17. Field selection excludes boolean fields (e.g., ISP, Photo, Origo, Mail, Talmundo, etc.)
18. Selected fields appear as columns in CSV export along with assigned date information
19. Default field selection includes: First Name, Surname, Email, SSN (unmasked - needed for hotel bookings), Room Number, Assigned Date Description, Assigned Date Value

## Dev Notes

### Architecture Context

This story implements employee tracking for important dates by adding an `assigned_employees` JSONB column to the `important_dates` table. This enables HR Admin to see who is assigned to each training date, review assignments, and export employee lists for operational scheduling.

**Integration with Story 8.7:**
Story 8.7 implemented capacity management (`max_spots`, `remaining_spots`) for dates. Story 8.8 extends this by tracking **which specific employees** are assigned, not just the count. The two features work together:

- `remaining_spots` = `max_spots` - `assigned_employees.length`
- When employee is assigned: decrement `remaining_spots` AND add employee to `assigned_employees` array
- When employee is unassigned: increment `remaining_spots` AND remove employee from `assigned_employees` array

[Source: docs/epic-8-enhanced-employee-management-features.md#story-88]

### Previous Story Context (Story 8.7)

**Capacity Management Foundation:**
Story 8.7 created the capacity tracking infrastructure with `max_spots` and `remaining_spots` columns. The `assignEmployeeToDate` service function in `src/lib/services/date-capacity.ts` already handles atomic date assignment using the `update_date_spots` RPC function with row-level locks.

Story 8.8 extends `assignEmployeeToDate` to also maintain the `assigned_employees` array alongside capacity updates. Both operations must happen atomically in the same transaction to prevent data inconsistency.

**Key Service Functions from 8.7:**

- `assignEmployeeToDate(employeeId, newDateId, oldDateId, dateType)` - Atomic date assignment with capacity management
- `releaseDateCapacity(dateId)` - Increments remaining_spots when employee is unassigned
- `update_date_spots` RPC function - PostgreSQL function handling transaction with row-level locks

Story 8.8 will update these functions to also manage `assigned_employees` array.

[Source: docs/stories/8.7.important-dates-capacity-management.md#dev-notes]

### Database Schema

**Migration SQL:**

```sql
-- Add assigned_employees JSONB column to important_dates table
ALTER TABLE important_dates
ADD COLUMN assigned_employees JSONB DEFAULT '[]'::jsonb;

-- Add column comment for documentation
COMMENT ON COLUMN important_dates.assigned_employees IS
  'Array of assigned employee objects: [{"id": "uuid", "name": "First Last", "email": "email@example.com", "room_number": 5}]';

-- Add GIN index for efficient JSONB queries (searching within array)
CREATE INDEX idx_important_dates_assigned_employees
ON important_dates USING GIN(assigned_employees);

-- Backfill assigned_employees from existing employee date assignments
UPDATE important_dates d
SET assigned_employees = (
  SELECT COALESCE(jsonb_agg(
    jsonb_build_object(
      'id', e.id::text,
      'name', e.first_name || ' ' || e.surname,
      'email', e.email,
      'room_number', e.room_number_shared
    )
  ), '[]'::jsonb)
  FROM employees e
  WHERE e.stena_date = d.id
     OR e.omc_date = d.id
     OR e.pe3_date = d.id
);
```

**Column Type:**

- `assigned_employees`: JSONB - Array of employee objects with structure: `[{"id": "uuid", "name": "string", "email": "string", "room_number": number | null}]`

**JSONB Advantages:**

- Flexible schema: Can add employee fields later without migration
- Efficient queries with GIN index: Can search for employees within array
- Native PostgreSQL JSONB functions for array manipulation: `jsonb_insert`, `jsonb_set`, `-` operator for removal

**Data Consistency:**
Both `remaining_spots` and `assigned_employees` must be updated together atomically. The existing `update_date_spots` RPC function from Story 8.7 will be extended to handle both updates in a single transaction.

**Story 8.8 Updates:**

1. Query employee details (id, first_name, surname, email, room_number_shared) before calling RPC
2. Build employee object: `{ id, name: \`${first_name} ${surname}\`, email, room_number }`
3. Extend `update_date_spots` RPC call to also update `assigned_employees`:
   - Add employee to new date's array
   - Remove employee from old date's array (if oldDateId exists)
4. Handle idempotency: Check if employee already exists in array before adding

**New RPC Function Parameters:**

```sql
CREATE OR REPLACE FUNCTION update_date_spots_with_employees(
  p_employee_id UUID,
  p_new_date_id UUID,
  p_old_date_id UUID,
  p_date_type TEXT,
  p_employee_data JSONB  -- NEW: employee object to add to assigned_employees
)
RETURNS VOID AS $$
BEGIN
  -- Lock rows
  PERFORM id FROM important_dates
  WHERE id IN (p_new_date_id, p_old_date_id)
  FOR UPDATE;

  -- Increment old date spots and remove from assigned_employees
  IF p_old_date_id IS NOT NULL THEN
    UPDATE important_dates
    SET
      remaining_spots = remaining_spots + 1,
      assigned_employees = assigned_employees - p_employee_data::jsonb
    WHERE id = p_old_date_id;
  END IF;

  -- Decrement new date spots and add to assigned_employees
  UPDATE important_dates
  SET
    remaining_spots = remaining_spots - 1,
    assigned_employees = assigned_employees || p_employee_data::jsonb
  WHERE id = p_new_date_id;

  -- Check constraint (capacity validation)
  IF (SELECT remaining_spots FROM important_dates WHERE id = p_new_date_id) < 0 THEN
    RAISE EXCEPTION 'No remaining spots available for this date';
  END IF;

  -- Update employee date field
  EXECUTE format('UPDATE employees SET %I = $1 WHERE id = $2', p_date_type)
  USING p_new_date_id, p_employee_id;
END;
$$ LANGUAGE plpgsql;
```

**Update `releaseDateCapacity` Function:**

Current function from Story 8.7 only increments `remaining_spots`. Story 8.8 updates it to also remove employee from `assigned_employees`:

```typescript
export async function releaseDateCapacity(
  dateId: string,
  employeeId: string // NEW parameter
): Promise<void> {
  // Build employee filter object for JSONB removal
  const employeeFilter = { id: employeeId };

  await supabase.rpc('release_date_capacity_with_employee', {
    date_id: dateId,
    employee_filter: employeeFilter,
  });
}
```

**New RPC Function:**

```sql
CREATE OR REPLACE FUNCTION release_date_capacity_with_employee(
  p_date_id UUID,
  p_employee_filter JSONB
)
RETURNS VOID AS $$
BEGIN
  UPDATE important_dates
  SET
    remaining_spots = remaining_spots + 1,
    assigned_employees = (
      SELECT jsonb_agg(elem)
      FROM jsonb_array_elements(assigned_employees) AS elem
      WHERE elem->>'id' != p_employee_filter->>'id'
    )
  WHERE id = p_date_id;
END;
$$ LANGUAGE plpgsql;
```

**3. Category Export with Date Range Filter (NEW):**

Location: `src/lib/services/export-service.ts`

Export all employees assigned to dates within a specific category and optional date range:

```typescript
interface CategoryExportOptions {
  category: 'Stena Dates' | 'ÖMC Dates' | 'PE3 Dates';
  dateFrom?: string; // ISO date string, optional
  dateTo?: string; // ISO date string, optional
}

/**
 * Export all employees assigned to dates within a specific category and date range.
 *
 * Query logic:
 * - Select employees where category date field (stena_date/omc_date/pe3_date) is NOT NULL
 * - Join with important_dates to get date details
 * - Filter by date range if provided
 * - Order by date value, then employee surname
 */
async function exportEmployeesByCategory(
  options: CategoryExportOptions
): Promise<string> {
  const { category, dateFrom, dateTo } = options;

  // Map category to employee date field
  const dateFieldMap = {
    'Stena Dates': 'stena_date',
    'ÖMC Dates': 'omc_date',
    'PE3 Dates': 'pe3_date',
  };
  const dateField = dateFieldMap[category];

  // Build query with optional date range filter
  let query = supabase
    .from('employees')
    .select(
      `
      id,
      first_name,
      surname,
      email,
      ssn,
      room_number_shared,
      ${dateField}:important_dates (
        date_description,
        date_value,
        category
      )
    `
    )
    .not(dateField, 'is', null);

  // Apply date range filter if provided
  if (dateFrom && dateTo) {
    query = query
      .gte(`${dateField}.date_value`, dateFrom)
      .lte(`${dateField}.date_value`, dateTo);
  }

  const { data: employees, error } = await query
    .order(`${dateField}.date_value`, { ascending: true })
    .order('surname', { ascending: true })
    .order('first_name', { ascending: true });

  if (error) throw error;

  // Generate CSV
  const headers = [
    'Employee Name',
    'Email',
    'SSN',
    'Room Number',
    'Assigned Date Description',
    'Assigned Date Value',
  ];

  const rows = employees.map((emp) => [
    `${emp.first_name} ${emp.surname}`,
    emp.email ?? '',
    emp.ssn ?? '', // Full SSN unmasked - needed for hotel bookings
    emp.room_number_shared?.toString() ?? 'N/A',
    emp[dateField]?.date_description ?? '',
    emp[dateField]?.date_value ?? '',
  ]);

  return generateCSV(headers, rows);
}

/**
 * Generate filename for category export
 */
function getCategoryExportFilename(
  category: string,
  dateFrom?: string,
  dateTo?: string
): string {
  const categorySlug = category.toLowerCase().replace(/\s+/g, '_');
  const timestamp = new Date().toISOString().split('T')[0];

  if (dateFrom && dateTo) {
    return `employees_${categorySlug}_${dateFrom}_to_${dateTo}_${timestamp}.csv`;
  }

  return `employees_${categorySlug}_all_${timestamp}.csv`;
}
```

### Business Rule Clarifications

**Employee Privacy - SSN Masking:**

When displaying assigned employees in the modal, SSN (Social Security Number) must be masked to show only the last 4 digits for privacy compliance. Format: `****-XXXX`

Full SSN is stored in database but only masked version displayed in UI. This applies to:

- Assigned Employees Modal employee list
- CSV export of specific date's employees

**Room Number Display:**

Room numbers are optional (can be null if `hotel_required = false` for employee). In assigned employees list:

- If `room_number` is not null, display number (e.g., "Room 5")
- If `room_number` is null, display "N/A" or "No room assigned"

**Modal Performance Threshold:**

Pagination triggers at >50 assigned employees per date. This threshold balances:

- UI performance (rendering 50 rows is fast)
- User experience (most dates have <50 employees)
- Edge cases (large ÖMC dates with 20 spots don't require pagination)

**Real-Time Update User Experience:**

When assigned_employees array updates while modal is open (another user assigns/unassigns employee), the modal should:

1. Refresh the displayed employee list automatically
2. Show brief visual indicator: "Updated" badge or subtle flash animation
3. Maintain current page/scroll position (don't jump to page 1)
4. Preserve search filter if active
