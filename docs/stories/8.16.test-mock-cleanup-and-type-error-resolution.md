## Dev Notes

### Architecture Context

This story continues the test cleanup work from Story 8.15, specifically addressing the 209 TypeScript type errors that remain after automated script cleanup revealed cross-type contamination issues.

**Inherited Context from Story 8.15:**

- **Starting Type Error Count:** 209 (increased from initial 102)
- **Root Cause:** Automated script `add-missing-employee-props.js` used pattern matching on `updated_at:` field
- **Contamination Impact:** Employee properties added to User, SessionUser, ColumnConfig, ImportantDate objects
- **Partial Cleanup Done:** 1,983 Employee properties removed from ImportantDate objects in Story 8.15

**Remaining Type Error Categories (from TEST_CLEANUP_ANALYSIS.md):**

1. **Cross-Type Contamination (~80-100 errors):**
   - Employee properties on User/SessionUser objects
   - Employee properties remaining on ColumnConfig objects
   - Properties added outside object closing braces (indentation issues)

2. **Missing Properties (~60-80 errors):**
   - Employee mocks missing repayment fields
   - Employee mocks missing new date/time fields
   - User/SessionUser mocks missing `last_active_at`
   - Hook return mocks missing `refetch` function
   - Component props missing required fields

3. **Invalid Enum Values (~15-20 errors):**
   - Invalid rank values: "JUN", "MID" (not in enum)
   - Should be replaced with valid values like "SEV", "CHEF"

4. **Type Mismatches (~15-20 errors):**
   - Termination API response type expectations (2 tests)
   - Property type mismatches (string vs string | null)
   - Array vs single object type mismatches

5. **Duplicate Properties (~10-15 errors):**
   - Script added properties that already existed
   - Need to remove duplicates

### Testing Standards

**Mock Object Best Practices:**

1. **Type-Specific Patterns:**
   - Employee: Check for `first_name` + `email` + `employee_number`
   - User: Check for `role` + `email`
   - ColumnConfig: Check for `column_name` + `db_column_name`
   - ImportantDate: Check for `event_name` + `event_type`

2. **Required Properties:**
   - Always include `id`, `created_at`, `updated_at`
   - Include all non-optional properties for the type
   - Use appropriate default values for optional properties

3. **Property Values:**
   - Use valid enum values only
   - Use correct types (number vs boolean for loneiva)
   - Use ISO date strings for date fields
   - Use null (not undefined) for nullable fields

### Systematic Cleanup Approach

**Step-by-Step Process:**

1. **Run Type Check First:**

   ```bash
   pnpm tsc --noEmit > type-errors-before.txt
   ```

   - Establish baseline count (should be 209)

2. **Clean Cross-Type Contamination:**
   - Focus on high-impact issues first (User/SessionUser contamination)
   - Verify each file individually after cleanup
   - Run type check after each category: `pnpm tsc --noEmit`

3. **Add Missing Properties:**
   - Use TEST_CLEANUP_ANALYSIS.md as reference
   - Add properties systematically by type
   - Verify type errors reduce with each commit

4. **Fix Enum and Specific Issues:**
   - Search and replace invalid enum values
   - Update specific test type expectations
   - Run type check after each fix

5. **Final Verification:**
   ```bash
   pnpm tsc --noEmit > type-errors-after.txt
   # Should show 0 errors
   pnpm build
   pnpm lint
   ```
