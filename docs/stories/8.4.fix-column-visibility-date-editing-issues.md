# Story 8.4: Fix Column Visibility, Column Settings Layout, and Date Editing Issues

## Status

**Done**

---

## Story

**As a** HR Admin user,  
**I want** to successfully toggle column visibility on/off, view the Column Settings table without horizontal scrolling at standard desktop resolutions, and edit date fields inline without errors,  
**so that** I can customize my dashboard view effectively, manage column permissions comfortably, and update employee date information efficiently.

---

## Background

Story 8.3 was deployed and marked as "Done" with all acceptance criteria claiming to be implemented. However, user testing revealed three critical issues that prevent the features from working as intended:

1. **Column Visibility Toggle Not Working**: HR Admin cannot "unclick" or hide columns after toggling visibility. The eye icon toggles but columns remain visible.
2. **Column Settings Horizontal Scroll**: The Column Settings table still shows a horizontal scrollbar at 1280px viewport width, despite AC6 claiming this was fixed.
3. **Date Field Inline Edit Error**: When attempting to inline edit date fields (Stena Date, ÖMC Date, PE3 Date) in the dashboard, an error occurs preventing the save operation.

These issues indicate that while the code was written for Story 8.3, either:

- The implementation has bugs that weren't caught in testing
- Manual responsive testing (Task 7.4-7.6) was skipped and issues weren't identified
- Integration between components isn't working correctly

This story addresses these gaps to ensure the features work as originally intended.

---

## Acceptance Criteria

### AC 1: Column Visibility Toggle Works Correctly

1. **Hide Column Functionality**: When HR Admin clicks the eye icon to hide a column in the Column Visibility popover menu:
   - The column must immediately disappear from the employee table
   - The eye icon must change to EyeOff (slashed) visual state
   - The column must remain hidden after browser refresh (localStorage persistence)
2. **Show Column Functionality**: When HR Admin clicks to show a hidden column:
   - The column must immediately reappear in the employee table at its original position
   - The eye icon must change to Eye (open) visual state
   - The visibility preference must persist across sessions
3. **Reset to Default**: Clicking "Reset to Default" must:
   - Show all columns that HR Admin has view permission for
   - Clear all visibility preferences from localStorage
   - Update the UI immediately without refresh
4. **Performance**: Toggling visibility must complete in <200ms with no visual lag or flicker
5. **No Regression**: Hidden columns must remain hidden when:
   - Navigating to other pages and returning to dashboard
   - Applying filters or search to the employee table
   - Sorting columns
   - Adding/editing employees

### AC 2: Column Settings Table Fits Desktop Viewport

1. **No Horizontal Scroll at 1280px**: At 1280px viewport width (standard laptop), the Column Settings table must display all columns without requiring horizontal scrolling
2. **All Content Visible**: All table content must be readable and accessible:
   - Column Name (full text, no truncation for names <30 characters)
   - Type, Category, Visibility badges
   - All role permission toggles (HR Admin, SDX, ÖMC, PAY, TPX)
   - Actions column (delete button)
3. **Responsive Width Distribution**: Columns must use available width efficiently:
   - Dynamic columns (Column Name) should flex to use available space
   - Fixed columns (Type, Actions) should use minimal necessary width
   - Permission toggles should be compact but tappable (min 40px touch target)
4. **No Content Overlap**: No columns should overlap, text should not be cut off, and all interactive elements should be fully clickable
5. **Larger Viewports**: At 1440px and 1920px, table should expand appropriately without excessive whitespace

### AC 3: Inline Date Editing Works Without Errors

1. **Successful Edit for Stena Date**: When HR Admin clicks a Stena Date cell and selects a new date from the dropdown:
   - The dropdown must show only "Stena Dates" category options (filtered correctly)
   - Upon selection, the save operation must complete without errors
   - The cell must update to display the new date description (e.g., "Fredag 14/2")
   - Success toast notification must appear
2. **Successful Edit for ÖMC Date**: Same behavior as Stena Date, but filtered to "ÖMC Dates" category
3. **Successful Edit for PE3 Date**: Same behavior, but filtered to "PE3 Dates" category and enforcing uniqueness (no duplicate assignments)
4. **Clear Date Operation**: Selecting "(None)" from any date dropdown must:
   - Clear the date value (set to null)
   - Display empty cell or "—" placeholder
   - Save successfully without errors
5. **Error Handling**: If save fails (network error, validation error):
   - Display specific error message in toast notification
   - Revert cell to previous value
   - Do not leave cell in broken/inconsistent state
6. **Read-Only Mode**: For non-HR Admin users, date cells must be read-only with tooltip explaining permission restriction

### Hypothesized Root Causes

**Issue #1 - Column Visibility Toggle:**

Possible causes:

1. `toggleColumnVisibility()` sets wrong value (undefined instead of false)
2. localStorage saves stringified "undefined" which parses incorrectly
3. Filtering logic: `columnVisibility[config.id] !== false` treats undefined as visible (should check `=== true`)
4. Race condition: localStorage update happens after render, causing stale state

**Issue #2 - Column Settings Horizontal Scroll:**

Calculated width breakdown:

- Drag: 64px + Name: 150px + Type: 80px + Category: 112px + Visibility: 96px + (6 roles × 96px) + Actions: 80px
- **Total minimum: ~1158px**
- With padding (8px per cell × 11 cells = 88px) and borders (~10px): **~1256px**
- **Result**: Fits within 1280px with only 24px margin

Possible causes:

1. Parent container has `max-width` or `padding` reducing available space
2. Table has extra padding/margin not accounted for
3. Browser zoom level not at 100%
4. Role columns are wider than w-24 due to content overflow
5. The `w-full` class on table conflicts with column width constraints

**Issue #3 - Date Editing Error:**

Possible causes:

1. `onSave` callback not properly bound or missing parameters
2. API expects different field name format (`stena_date` vs `Stena Date`)
3. Sending description instead of UUID to API
4. `allImportantDates` is empty/undefined when EditableDateCell renders
5. PE3 uniqueness check fails even for non-PE3 dates (incorrect logic)
6. Network error not caught and displayed
7. Supabase RLS policy blocks update operation
8. Missing `await` causing race condition in save operation
