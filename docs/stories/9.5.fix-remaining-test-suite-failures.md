### Translation Reference

All Swedish translations are located in `/messages/sv.json`. The file is structured as follows:

```json
{
  "common": { ... },      // Common UI text (buttons, actions)
  "dashboard": { ... },   // Dashboard-specific text
  "forms": { ... },       // Form field labels and validation
  "modals": { ... },      // Modal dialog text
  "admin": { ... },       // Admin interface text
  "dates": { ... },       // Important dates text
  "errors": { ... }       // Error messages and validation
}
```

### Testing Approach

**For Translation Fixes:**

1. Run individual test file to identify failing assertions
2. Check `/messages/sv.json` for correct Swedish translation
3. Update test query/expectation with Swedish text
4. Use regex patterns (`/text/i`) for case-insensitive matching
5. Verify test passes

**Example Fix:**

```typescript
// Before (English)
expect(screen.getByLabelText(/column name/i)).toBeInTheDocument();

// After (Swedish)
expect(screen.getByLabelText(/Kolumnnamn/i)).toBeInTheDocument();
```

**For API Mocking Issues:**

1. Identify relative URL parsing errors
2. Update MSW handlers to use absolute URLs
3. Add proper base URL configuration if needed
4. Verify mock responses match expected format

**Example Fix:**

```typescript
// Before (causes URL parse error)
http.get('/api/important-dates/available-pe3', ...)

// After (absolute URL)
http.get('http://localhost:3000/api/important-dates/available-pe3', ...)
```

### Testing Standards

**Source:** [docs/architecture/testing-strategy.md]

1. **Test Organization:**
   - Unit tests: Component behavior, service logic, utilities
   - Integration tests: API routes, component interactions, database operations
   - Test files co-located with implementation (when appropriate)

2. **Testing Framework:**
   - **Vitest** for unit and integration tests
   - **React Testing Library** for component tests
   - **MSW (Mock Service Worker)** for API mocking

3. **Test Coverage Goals:**
   - Overall: 70%+
   - Business logic: 90%+
   - UI components: 60%+
   - API routes: 85%+

4. **Best Practices:**
   - Use descriptive test names
   - Test behavior, not implementation
   - Avoid testing library internals
   - Clean up after each test (afterEach hooks)
   - Use proper mocking strategies

5. **Translation Testing Pattern:**
   - Always reference `/messages/sv.json` for expected text
   - Use case-insensitive regex: `/text/i`
   - Document translation key dependencies
   - Verify text from correct JSON path

### Common Issues and Solutions

**Issue 1: Text Not Found in Document**

- **Cause:** Test expects English, app renders Swedish
- **Solution:** Update test to use Swedish text from `sv.json`

**Issue 2: URL Parsing Errors**

- **Cause:** MSW handlers use relative URLs
- **Solution:** Use absolute URLs or configure base URL

**Issue 3: Mock Setup Failures**

- **Cause:** Nested API calls not properly mocked
- **Solution:** Add all required mock handlers for dependent calls

**Issue 4: State Synchronization Issues**

- **Cause:** Component state not updating in test environment
- **Solution:** Use `waitFor()` for async state updates, add proper cleanup

### Performance Considerations

- Test execution should remain under 60 seconds total
- Individual test files should complete in < 5 seconds
- Use `describe.concurrent` for independent test suites when appropriate
- Avoid unnecessary re-renders in component tests
