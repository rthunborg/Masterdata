# Story 14.1: ÖMC + Masterdata Completion Follow-up

## Status

**Ready for Development**

---

## Story

**As an** HR admin,  
**I want** to receive an email when an employee's required masterdata is still incomplete 3 days after their ÖMC date,  
**so that** I can follow up quickly and keep onboarding/compliance moving.

---

## Acceptance Criteria

**AC1:** Given an employee with `omc_date = D`, when the job runs on date >= D + 3 days, the employee is evaluated.

**AC2:** If any required boolean masterdata field is false OR `loneniva` is empty/null, an email is sent to all hr_admin emails.

**AC3:** The email includes:
- Employee full name (and optionally id)
- `omc_date` value
- A list of exactly those fields failing the rule:
  - boolean fields that are false (excluding `hotel_required`, `crew_done`)
  - `loneniva` if empty/null

**AC4:** If all required fields are complete, no email is sent.

**AC5:** The same employee should not generate duplicate emails every day forever.
- Add a "notification sent" marker, e.g. `omc_masterdata_reminder_sent_at` timestamp.
- Once sent, don't resend unless `omc_date` changes or fields regress and you explicitly want re-alerting (define as default: no resend).

**AC6:** Timezone correctness: "3 days passed" is calculated using Europe/Stockholm calendar days.

---

## Business Rules

1. An employee may have `omc_date` set (date they completed ÖMC training).
2. When 3 full days have passed after `omc_date`, the system checks completion status.
3. **Completion status definition:**
   - All boolean masterdata fields must be `true`, except:
     - `hotel_required` (ignored)
     - `crew_done` (ignored)
   - `loneniva` (enum) must be non-null / non-empty.
4. If completion status is not met:
   - Send an email notification to each hr_admin user's assigned email.
   - Email states that 3 days have passed since employee X completed ÖMC, and specifies which fields are still missing/false/empty.
5. **Idempotency:** Once a notification is sent for an employee, don't resend unless:
   - `omc_date` changes (new date triggers new evaluation)
   - Fields regress (optional: can be configured to re-alert, default: no resend)

### Query Approach

```sql
SELECT * FROM employees
WHERE omc_date IS NOT NULL
  AND omc_date <= CURRENT_DATE - INTERVAL '3 days'
  AND (omc_masterdata_reminder_sent_at IS NULL 
       OR omc_date > omc_masterdata_reminder_sent_at::date)
```
